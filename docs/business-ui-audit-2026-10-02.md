# 业务页面 UI 排查记录（2026-10-02）

## 范围与方法

基于提交 `69f4f20`，排查用户报告的三类问题：控件尺寸不一致、未保存返回时缺乏可见反馈、搜索选择器分页溢出。工作区开始时无未提交改动。

三个 `gpt-6-luna` 子 agent 分别只读检查购销与退货、基础资料与库存、往来与打印；主 agent 使用 Chromium 逐页复核。覆盖 21 个功能页面、23 个路由状态，以及 5 类新建弹窗；采购、销售新建和编辑分别计入路由状态。库存调整详情和往来记录子组件一并检查。首页已经是业务工作台，纳入范围；原脚手架系统管理、账号、通知和示例页面排除。

浏览器使用隔离的 API 响应数据，在 `1440×1000`、`1024×1000` 两种桌面窗口下测量。所有业务 API 请求由测试脚本拦截，禁止写请求，不接触业务库。此次是 UI 专项排查，没有执行真实保存、过账或打印 PDF 验收。

## 已确认的问题

### A：四个列表的状态选择框尺寸不统一

| 页面 | 来源 | 实测 |
| --- | --- | --- |
| 采购入库列表 | `web/src/pages/business/purchases.tsx:174` | 状态框高 24px，输入框高 36px |
| 销售出库列表 | `web/src/pages/business/sales.tsx:48` | 状态框高 24px、宽 102px；同列输入框宽 240px |
| 采购退货列表 | `web/src/pages/business/purchase-returns.tsx:38` | 状态框高 24px，输入框高 36px |
| 销售退货列表 | `web/src/pages/business/sale-returns.tsx:38` | 状态框高 24px，输入框高 36px |

共同使用不存在的 `h-control`。Tailwind 只定义了 `control-sm/md/lg`，公共 Input/Select 的默认高度为 `h-control-md`。销售状态框还缺少 `w-full`，圆角及边框样式也未复用公共组件。

另外，共享搜索选择器的空值、单行触发按钮高 38px，邻近 Input/Select 高 36px。来源为 `components/common/paged-record-select.tsx:86` 的 `!h-auto`、上下各 8px padding，加上 20px 行高和两侧边框。影响采购/销售列表及录单、往来余额/明细。选中长描述后的自动增高有助于完整显示资料，应保留；需要统一的是空值和单行状态的基本高度，不能直接把所有状态锁死为 36px。

### B：采购和销售录单的离开确认在视口之外

来源：`purchase-form.tsx:63,281`、`sale-form.tsx:65,322`。

新建、编辑均启用 `useBlocker`，但离开确认是放在长表单之后的普通 `div`。输入备注或选择交易对象后，从顶部返回时，路由确实被拦截，确认提示却位于 1000px 高的视口之外，且没有弹层定位、自动滚动或焦点引导。因此页面停留，用户看不到下一步操作。

之前的最小复现已验证：选供应商后，两个返回入口都会被拦；滚动到确认区后，“继续录单”保留输入，“确认离开”正常返回。此次再次分别复核了购销新建和编辑。

来源链接的 loading 闪烁来自 `components/layout/use-route-navigation-loading.ts:45` 对链接点击意图的捕获；它并不表示路由已经通过离开保护。这是反馈问题的背景，不是跳转失败的根因。

### C：六个功能页面的共享搜索分页布局不适配容器

来源：`components/common/paged-record-select.tsx:108` 内嵌通用 `Pagination`；`components/common/pagination.tsx:43` 使用按浏览器视口判断的 `md:flex-row`。

| 页面 | 搜索控件 | 复核结果 |
| --- | --- | --- |
| 采购列表 | 供应商、商品 | 240px 容器中“下一页”向右溢出约 83px，统计文字高 80px（四行） |
| 销售列表 | 客户、商品/服务 | 同上 |
| 往来余额 | 往来单位 | 同上 |
| 往来明细 | 往来单位 | 同上 |
| 采购录单（新建/编辑） | 供应商、明细商品 | 1440px 窗口正常；1024px 窗口下统计文字被挤为四行 |
| 销售录单（新建/编辑） | 客户、关联直送采购、明细商品 | 同上 |

两条结果、仅一页就能复现，无需很多数据。之前的 270px 最小复现实测溢出约 53px。仅减少左右 padding 无法消除问题；临时使用纵向布局后改善，紧凑分页布局在 240px、270px 宽度下均无溢出。

库存调整和库存流水的商品筛选使用另一套自定义组件，不能因为也有商品搜索就归入该共享根因。库存调整弹窗的自定义分页在极窄宽度下存在类似风险，但本轮桌面窗口未确认溢出；保留为后续窄容器检查项，不计入已确认的六页。

## 额外观察：未保存离开策略不一致

以下行为与 B 不同：没有拦住返回，而是直接离开或关闭。需要在修复时统一“已经编辑的表单”与“明确放弃操作”的提醒策略。

| 页面/状态 | 浏览器验证 | 代码入口 |
| --- | --- | --- |
| 仓库资料 | 改名后返回来源，无提醒；重新进入恢复原值 | `warehouse.tsx:2` |
| 经营者打印资料 | 修改后返回来源，无提醒；重新进入恢复原值 | `print-profile.tsx:14,48` |
| 收付款 | 输入金额后返回来源，无提醒；重新进入金额清空 | `partner-funds.tsx:81` |
| 退款 | 同上 | 同一组件，`kind="REFUND"` |
| 期初应收/应付 | 输入金额后返回来源，无提醒；重新进入金额清空 | `opening-balances.tsx:72` |
| 商品与服务新建弹窗 | 修改后点击 X，无提醒；重开输入清空 | `products.tsx:267` |
| 往来单位新建弹窗 | 同上 | `partners.tsx:223` |
| 库存调整新建弹窗 | 填数量后点击 X，无提醒；重开输入清空 | `inventory-adjustments.tsx:327` |
| 采购退货新建弹窗 | 填备注后点击 X，无提醒；重新进入输入清空 | `purchase-returns.tsx:41` |
| 销售退货新建弹窗 | 同上 | `sale-returns.tsx:41` |

五类弹窗的编辑路径复用相同的关闭处理，代码检查也未发现脏状态保护；编辑弹窗未逐一做浏览器输入回放。公共 `FormDialog` 默认支持 Escape 和遮罩关闭，页面的取消回调没有检查修改状态。本轮实测关闭途径为 X，其他关闭途径的判断来自代码。

取消收付款或期初的“提交确认弹窗”会回到原表单，不能据此说原表单输入丢失。往来记录的冲销原因取消也属于明确放弃的小流程，本轮不将其计作上述十项已确认输入丢失。

## 修复与回归建议

1. 采购/销售录单使用现有确认弹窗展示离开决策，保留原 blocker、保存待核实和过账待核实语义。测试提示必须位于当前视口，且焦点可操作；继续编辑保留输入、确认离开到正确来源。
2. 搜索选择器使用适合窄容器的分页布局，不改变大表格的默认分页布局。覆盖 240/270px 容器、1024/1440px 窗口、零/两条/多页结果、加载和失败态。
3. 四个状态筛选复用公共 Select；统一搜索触发按钮空值和单行高度，保留长描述可换行。
4. 统一其余业务编辑表单的离开/关闭策略，分别覆盖内部返回、菜单跳转、刷新，以及弹窗 X、Escape、遮罩和取消。

现有 `web/tests/phase5-purchase-drafts.mjs:39` 通过 Playwright 点击离开提示中的按钮；点击会自动滚动到目标，未断言用户点击返回后提示就在视口内，因此漏掉 B。共享搜索验收也需要明确检查容器边界和统计文字行数，不能只验证翻页按钮存在。
