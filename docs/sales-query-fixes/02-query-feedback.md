# 销售查询错误反馈、合计加载状态与页码校正

## Parent

https://github.com/EziosWJ/simple-inventory/issues/66

## What to build

让销售查单和查明细在条件无效、请求加载、失败及结果数量减少时给出准确反馈，不把旧合计或不存在的页码呈现为当前结果。

## Acceptance criteria

- [x] 两个视图都显示日期起止反向的校验提示；无效条件不发送查询，快捷条件及档案选择触发查询时也使用统一校验。
- [x] 来源单详情读取失败有独立可见提示和重试，不能在明细视图中被单据列表的错误状态隐藏。
- [x] 列表与合计表达同一查询状态：加载期间隐藏旧数字或明确标为上一轮结果，不当作新条件的正常合计。
- [x] 失败显示合计不可用及重试；只有成功的空结果显示零合计，失败不能伪装成零销售。
- [x] 过期或失败响应不能覆盖较新的列表、汇总或详情；保留输入和已应用条件。
- [x] 刷新或业务动作后结果缩减导致页码越界时，校正实际查询页并重查；分页文本、URL 页码和显示记录一致；空结果回第一页。
- [x] 真实浏览器覆盖延迟、失败、快速切换、非法日期及末页记录减少；通过前端 lint/build。
