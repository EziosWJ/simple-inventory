# 07：销售整单出库、应收入账、历史快照与取消

**GitHub issue:** [#21](https://github.com/EziosWJ/simple-inventory/issues/21) · `ready-for-agent`

## Parent

Phase 4 规格：https://github.com/EziosWJ/simple-inventory/issues/14

## What to build

经营者确认销售草稿，将实物扣库存、服务计入成交和应收，查看最终快照和前后影响；库存不足整单拒绝，录错取消反向处理但保留原收款。

## Acceptance criteria

- [ ] 过账携带最新草稿版本，事务内重新校验客户角色/启用状态、商品类型/单位/启用；同商品按合计扣减，不因分行绕过库存约束。
- [ ] 实物减少共享真实库存并生成可识别销售来源的流水；服务计入行/单据金额与客户应收，纯服务不得建立库存行，零价实物仍扣库存。
- [ ] 全部库存、金额、状态、商品锁和审计同事务；任一实物不足或写入/金额溢出拒绝全单，混合单服务应收也不部分生效。
- [ ] 冻结客户名称、送货联系人/电话/地址、经营者抬头/电话/地址与商品资料，包括空值；已过账详情与重读不回退当前档案。
- [ ] 记录实际操作人与系统生效时间，业务日期单独展示；源单可以从库存或往来明细打开，商品修改历史锁覆盖所有实物来源。
- [ ] POSTED 内容锁定；取消整单反向库存/应收并保留原收款，可形成待退款或被新正确销售抵减；生效退货后原单取消拒绝，后续退货任务接入约束。
- [ ] 并发两单扣同商品不超扣，同单重试防重，过账/编辑/取消竞争与商品资料修改竞争一致；取消仍不能产生负库存。
- [ ] 双库覆盖赠品、同商品汇总不足、混合/纯服务、快照空值、已收款取消、余额流水累计及审计回滚；真实页面演示采购库存→销售过账→取消。
- [ ] 沿用 JWT 和已登录账号业务范围，实际菜单按角色接入并授予 ADMIN，拒绝未登录请求；不以 mock 权限替代后端认证。
- [ ] 所需 schema/seed 使用 PostgreSQL/SQLite 逻辑版本同步的增量 Goose 迁移，不改旧版本、不用 AutoMigrate；保持现有业务数据与 API 兼容。
- [ ] 本任务业务维护与操作审计同事务，错误明确且保留表单输入；新增/修改 REST API 源注解与 Swagger 重新生成同步。
- [ ] 以公开 HTTP 和真实双库验证本任务行为，新增 contract 名含 Postgres/SQLite 并确实被门禁执行；相关后端 tests/vet、前端 lint/build 和数据库检查完成，报告失败、跳过和未执行项。
