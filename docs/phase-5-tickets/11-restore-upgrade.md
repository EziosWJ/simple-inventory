# 11：整套恢复与升级回退演练

**GitHub issue:** [#50](https://github.com/EziosWJ/simple-inventory/issues/50) · `ready-for-agent`

## Parent

[Phase 5 规格 #39](https://github.com/EziosWJ/simple-inventory/issues/39)

## What to build

维护者将已验证备份恢复到新的数据库和持久目录，实际启动应用并核对业务/文件，再演练升级失败时恢复发布前数据及旧应用。

## Acceptance criteria

- [ ] 交付恢复、升级及回退的可执行步骤，恢复使用新库和新目录，不覆盖正在运行的业务数据。
- [ ] 读取备份校验、发布及迁移版本，恢复必要配置、数据库和上传文件；不混用不同批次的文件和数据库。
- [ ] 真实导入后启动正确版本，验证 HTTPS/就绪、独立账号、采购销售/明细/快照、库存与往来流水及余额、文件读取和打印。
- [ ] 恢复后执行一笔代表性业务写入并核对库存/往来与审计，证明应用可用而非仅能列出备份文件。
- [ ] 升级前生成整套备份，显式迁移并做版本和核心业务冒烟；迁移/校验失败时按既定步骤处理，不隐式向生产放行。
- [ ] 回退采用发布前备份加匹配旧应用，不承诺 migration down 或旧二进制读新 schema；明确回退恢复点及之后业务记录处理边界。
- [ ] 损坏/不完整/不匹配备份演练被明确拒绝并不破坏原环境，记录命令结果、版本、恢复核对及失败路径。
- [ ] 所有演练限隔离环境，正式云服务器和真实业务数据仍按后续上线安排处理。
