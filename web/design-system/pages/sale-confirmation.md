# 销售保存与过账确认

销售录单的“保存并过账”使用 `FormDialog` 单据布局。正文先列销售单身份、客户、业务日期和实际执行动作，再显示金额与行数概览、可核对的成交明细，以及确认后库存和客户往来方向的影响。商品成交行保留相同商品的不同价格；库存影响按商品 ID 与单位合并。服务不产生库存，零金额不产生往来金额流水。送货联系人、电话和地址放在默认折叠的辅助区。

新建／编辑保存并过账与原单安全重试采用不同标题和确认按钮。保存、待核实、过账阶段在弹窗内显示。现有保存回执、同 ID／版本校验、待核实标识、恢复入口和离开保护继续由销售录单页负责；确认外观不改变这些请求与恢复规则。

销售列表草稿过账使用相同的只读单据预览。请求期间禁用提交与关闭，防止重复过账；失败原因留在当前弹窗，并提示从详情核实单据状态。关闭预览不发送写请求。

验证由 `web/tests/document-sale-modals.mjs` 使用隔离 mock API 和独立 Vite 端口 4212 覆盖，包含保存失败不继续过账、保存后过账失败、响应丢失后读取真实状态、同商品分价行与库存汇总、混合实物／服务和纯服务零金额，以及短屏长单和窄屏布局。截图保存在 `/tmp/issue90-sale-confirm.png`、`/tmp/issue90-sale-post-failed.png` 和 `/tmp/issue90-sale-confirm-narrow.png`。
