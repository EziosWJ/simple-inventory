# 01：商品与服务建档、详情和分页查询

**GitHub issue:** [#2](https://github.com/EziosWJ/simple-inventory/issues/2) · `ready-for-agent`

## Parent

- Phase 2 基础资料规格：https://github.com/EziosWJ/simple-inventory/issues/1

## What to build

经营者可以从真实业务菜单建立不同规格的实物商品与安装、维修服务，填写单一基本单位、可选参考价与描述信息，随后查询列表、筛选和查看详情。本任务交付完整建档查询路径，包括持久化、认证 API、UI、审计、双库验证和 Swagger，完成后可独立演示。

## Acceptance criteria

- [ ] 新增商品与服务菜单并授权 ADMIN，已登录用户可以进入页面；未登录 API 请求被拒绝，接口沿用本轮已确认的登录认证范围。
- [ ] 商品与服务区分类型；名称、类型、基本单位必填；品牌、型号、规格、分类文本、参考采购价、参考销售价、备注选填，新资料默认启用。
- [ ] 不同规格可以同名建档，商品列表展示型号与规格；服务不包含库存字段或出入库行为。
- [ ] 空编码自动生成，手工编码统一大写并去除首尾空格；商品档案范围内编码唯一，并发冲突和自动编码碰撞不覆盖已有记录。
- [ ] 人民币参考价可空或为零，两位小数精确保存与读取；负数、超精度、溢出和无效输入被拒绝，UI 区分空价与零价。
- [ ] 可按编码、名称、品牌、型号、规格关键词查询，并按类型、分类、启用状态筛选；分页结果、总数、稳定排序与现有分页契约一致。
- [ ] 可以查看已保存商品与服务的完整详情，表单错误明确反馈并保留输入。
- [ ] PostgreSQL/SQLite 的资料与菜单迁移逻辑版本同步，数据库约束与应用校验均落实，空库和升级路径通过验证。
- [ ] 新增资料与操作审计同事务提交；审计失败时新增资料整体回滚，双库行为验证通过。
- [ ] 公开 HTTP 行为覆盖登录、建档、价格精度、无效输入、详情、筛选分页、编码规范化与并发唯一性，新增 contract 被数据库检查入口实际执行。
- [ ] 完成页面建档查询演示、后端 tests+vet、前端 lint/build、双库相关检查；Swagger 从源注解重新生成，记录未执行项。
- [ ] 不实现编辑、启停、删除、库存、SN 或导入导出；后续编辑与启停使用本任务的同一份档案。
