# 16：往来明细分页、实际生效期间对账与 A4 打印

**GitHub issue:** [#30](https://github.com/EziosWJ/simple-inventory/issues/30) · `ready-for-agent`

## Parent

Phase 4 规格：https://github.com/EziosWJ/simple-inventory/issues/14

## What to build

经营者按往来单位和客户/供应商方向查所有金额变动及来源，选择期间打印期初、期间变动和期末余额，与交易对方对账。

## Acceptance criteria

- [ ] 交付往来余额/明细账真实菜单与认证分页 API，客户/供应商方向分开，支持欠款/待退款/净零及停用历史单位，按单位/方向/实际生效期间过滤。
- [ ] 明细展示期初、采购/销售、退货、普通收付款、退款、交易取消及往来冲销，实际执行人、业务日期/生效时间、前后余额和来源号准确；可打开正确业务详情。
- [ ] 稳定按生效时间和 ID 排序，分页总数/过滤一致，时区表达与前端日界一致，时间上下界采用含下界不含上界。
- [ ] 期间期初来自起始时刻之前所有已生效金额，期间完整流水和期末可核对；不由当前余额倒推、不被列表分页截断。
- [ ] 跨期补录/取消/冲销仅计实际发生期间，旧期间打印数字不被后续记录改写；原始记录/反向来源保留。
- [ ] 提供 A4 纵向完整期间对账打印，单位/方向/期间标识、期初/期间/期末金额、页码、长单分页及末页合计；不提供 Excel 导出或逐单未结分配。
- [ ] 双库验证所有已实现来源、零/负余额、历史期间/同秒排序/时间边界、当前档案变更与来源链接；浏览器演示跨页明细与多页对账打印。
- [ ] 沿用 JWT 和已登录账号业务范围，实际菜单按角色接入并授予 ADMIN，拒绝未登录请求；不以 mock 权限替代后端认证。
- [ ] 所需 schema/seed 使用 PostgreSQL/SQLite 逻辑版本同步的增量 Goose 迁移，不改旧版本、不用 AutoMigrate；保持现有业务数据与 API 兼容。
- [ ] 本任务业务维护与操作审计同事务，错误明确且保留表单输入；新增/修改 REST API 源注解与 Swagger 重新生成同步。
- [ ] 以公开 HTTP 和真实双库验证本任务行为，新增 contract 名含 Postgres/SQLite 并确实被门禁执行；相关后端 tests/vet、前端 lint/build 和数据库检查完成，报告失败、跳过和未执行项。
