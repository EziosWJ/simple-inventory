# 独立直送单与普通销售采购来源

现有直送业务需要分别录入并过账采购与销售，普通销售也缺少跨供应商的采购来源追溯。需求访谈已确认采用单供应商、单客户的独立直送单，客户收货后一次确认，在同一事务中生成并过账采购、销售；普通销售另外记录采购明细及来源数量，支持关联多个采购单，以减少直送重复操作并支持配件售后追溯。

普通销售采购来源不沿用原直送整单实物数量一致、一张采购最多关联一张有效销售的限制。装机继续按配件销售和扣库存，按整机经营时沿用整机入库、销售，本次不引入组装转换。

直送确认保留采购增加、销售减少的成对库存流水，两边同事务完成后库存净变化为零。普通销售采购来源为选填的人工追溯记录，不占用采购数量；按销售明细记录相同商品的已过账采购明细和来源数量，同一销售明细的来源数量合计不超过销售数量。

直送取消时整笔取消原直送及对应采购、销售；经营者随后按实际情况独立新建直送单，取消与新建互不影响，不建立旧新单更正链或联动事务。客户退回店内时保留采购，沿用销售退货增加库存。新直送单生成的两单更正统一由直送入口办理，保留历史单据和操作记录。

普通销售过账后允许补填或更正采购来源并保留修改审计，不改变库存或往来。

取消保留原收付款，按往来单位总余额结算，实际退款另行记录；独立新单自行填写业务日期，取消与新单过账流水分别按实际操作时间生效。旧版直送保留历史数据与原操作规则，新业务使用独立直送单，不强制转换旧单。

客户先退到店内再退供应商时沿用销售退货、采购退货路径；已有生效退货时禁止整单取消，不自动取消关联退货。打印复用销售送货单，不新增直送打印模板。

用户已确认各项业务决定并授权发布规格、任务和开始实现，本 ADR 已接受。T01～T05 实现与统一验收记录见[进度文档](../direct-delivery-redesign-progress.md)；代码提交仅保存在本地。完整讨论见 [需求讨论](../direct-delivery-redesign-plan.md)，正式规格见 [GitHub #78](https://github.com/EziosWJ/simple-inventory/issues/78)。
