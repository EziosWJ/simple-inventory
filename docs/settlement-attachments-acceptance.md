# 往来业务附件交付记录

规格：[GitHub #63](https://github.com/EziosWJ/simple-inventory/issues/63)。本地实现已完成；未提交 Git、未部署，未操作现有业务数据库。

## 已实现

- 收付款、退款、期初应收／应付共用附件能力；历史记录可补传。
- PNG、JPG/JPEG、PDF，单个最多 10 MiB（界面显示 10 MB 并说明），每条最多五个有效附件，全部可选。后端检查实际图片及 PDF 结构；PDF 返回规范 MIME。
- 新建时上传中或失败阻止保存，保留表单和成功项；支持失败重试、主动移除失败项后继续。业务保存与初始附件绑定、审计事务一致，幂等重试核对初始附件集合。
- 列表显示有效数量，详情提供补传、图片放大、PDF 查看、下载、移除和历史。移除保留原文件与操作信息且释放名额，冲销后有效及历史附件均只读。
- 关联保存上传人、上传时间、绑定人、绑定时间、移除人和移除时间；附件操作不影响金额或余额。
- 对应业务菜单授权管理附件：期初 `business:opening-balance`、收付款 `business:settlement`、退款 `business:refund`。具有 `business:partner-ledger` 查询权限也可查看已绑定的有效及历史附件，但不能上传或补删；业务菜单授权同时可查阅本业务附件。
- 未绑定临时附件仅上传者可读。业务附件在通用文件列表中隐藏；直接文件读取检查业务权限，通用修改模块、删除、批量删除和停用不能破坏已绑定及历史附件。
- PostgreSQL/SQLite schema migration 同步增加版本 26 的附件关联表；旧记录默认没有附件，原往来数据保留。未增加菜单，seed 版本和菜单数量不变。
- API 源注解与生成 Swagger 已同步；新增列表、补传、移除接口，原业务请求可选 `attachmentIds`，原查询响应增加 `attachmentCount`。

## 临时文件清理

临时附件以最后活动时间续期。表单每分钟和恢复可见时通过鉴权文件详情续期；24 小时没有活动且没有任何业务关联的文件可清理。API 启动及每小时清理，业务附件上传也触发清理；先锁定并标记临时文件不可绑定，再删除原文件，成功后清理临时元数据，物理删除失败可重试。已绑定、已移除、已冲销附件均不满足清理条件。

浏览器关闭或长时间离线导致临时附件过期时，重新续期会把对应文件标为失败，用户可从仍保留的本地选择项重试；该过程不修改业务余额。

## 环境与保留事项

- Docker Desktop 在本 WSL 环境不可用。PostgreSQL 验证使用在 `/tmp` 构建的真实 PostgreSQL 17.6，通过只适配现有测试夹具启动命令的本地脚本启动隔离实例；验证 SQL、事务、HTTP 与备份恢复均使用真实数据库，不跳过 PostgreSQL contract。测试结束自动停止并删除实例。Docker 容器生命周期本身未验收。
- 当前工作区的全量 UI 脚本还包含此前未提交的销售详情用例。该用例循环复用 `saleDetailRecord.directDocuments`，前一轮清空后，后续已过账场景找不到 `PI-UI-001` 按钮而超时。本次没有修改销售页面或该用例；仅让原布局检查排除隐藏文件输入。原销售改动保留，失败不属于附件功能。
- 使用前对目标环境执行 `task db:migrate`，或 SQLite 模式的 `task db:migrate:sqlite`，并重启 API 使新路由和清理任务生效。
