# 04：往来单位编辑、停用和恢复

**GitHub issue:** [#5](https://github.com/EziosWJ/simple-inventory/issues/5) · `ready-for-agent`

## Parent

- Phase 2 基础资料规格：https://github.com/EziosWJ/simple-inventory/issues/1

## What to build

经营者可以编辑往来单位的编码、分类、业务身份、联络与开票信息，停用不再合作的交易对方，并在关系恢复时启用原档案。资料保留，可独立演示从编辑到停用恢复的维护闭环。

## Acceptance criteria

- [ ] 从列表与详情可编辑全部已定义资料，沿用建档的必填、选填与编码规范化规则。
- [ ] 可在客户、供应商和双重身份间调整，但至少保留一种业务身份；无身份修改被拒绝且原资料保持不变。
- [ ] 编码可修改，内部身份不变；与其他启用或停用档案冲突时明确报错，不改变资料。
- [ ] 可更新或清空选填联络和开票资料；成功后列表及详情展示一致。
- [ ] 停用与恢复设置明确目标状态，重复设置同一状态后仍保持一致；停用资料可筛选、查看、编辑和恢复。
- [ ] 不存在删除入口或接口，不因停用释放编码；未登录请求被拒绝，沿用本轮确认的权限范围。
- [ ] 编辑及状态修改和操作审计分别在同一事务提交，双库验证审计失败时业务修改回滚。
- [ ] 公开 HTTP 测试覆盖双重身份修改、最少一种身份、编码编辑冲突、选填资料清空、状态幂等、停用后维护和恢复。
- [ ] 完成页面维护演示、相关后端、前端、双库检查；任何迁移逻辑版本同步，Swagger 重新生成并记录未执行项。
- [ ] 后续单据拒绝选用停用资料留到单据阶段，不提前实现采购或销售接口。
