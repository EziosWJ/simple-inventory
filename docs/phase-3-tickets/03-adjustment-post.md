# 03：库存调整整单过账、非负余额与商品引用锁定

**GitHub issue:** [#10](https://github.com/EziosWJ/simple-inventory/issues/10) · `ready-for-agent`

## Parent

Phase 3 库存基础规格：https://github.com/EziosWJ/simple-inventory/issues/7

## What to build

经营者核对已保存草稿后可整单过账，将期初和日常增减正式记入库存；一项库存不足则整单失败。过账详情展示已生效数量和过账时商品资料，同时在商品维护页面阻止修改已有库存历史的类型和基本单位。该路径从草稿界面贯通真实余额、流水、商品约束和双库验证。

## Acceptance criteria

- [x] 新增明确过账操作及整单影响确认，携带用户核对版本；仅最新 DRAFT 可首次生效，成功后 POSTED，记录实际操作人、系统生效时间和不可编辑明细。
- [x] 事务内重新核对商品为启用实物、类型与单位和用户确认内容一致；已停用、已变为服务或单位变化时整单拒绝，提示重新选择商品并确认数量。
- [x] 多商品混合增减整单一次生效，同商品不重复；首次增加建立余额，减少依据事务内最新余额校验，任何商品结果小于零均拒绝。
- [x] 每行生效追加不可变原始流水，保存有符号变动、前后余额、原因/说明、实际操作人、时间及来源单据/明细；无修改删除流水入口。
- [x] 已过账明细和流水保存过账时商品编码、名称、型号、规格、单位快照，保留内部 ID；详情以快照展示，不随当前描述编辑改写。
- [x] 过账界面可查看最终快照、数量及过账信息，验证初始录入和混合增减确已生效；本任务不交付完整库存/流水分页页面，后续任务复用真实记录。
- [x] 库存余额、全部流水、单据状态及审计在同一数据库事务提交；一项不足或审计/写入失败全部回滚，保留原草稿，不留部分结果。
- [x] 重复点击、响应丢失重试及同单并发过账仅生效一次；过期内容或相反状态返回明确冲突，已取消单不能过账。
- [x] 库存为 3 的两张单同时各减 2，最多一张成功；同商品首次增加并发不重复建立余额或丢失更新，多商品事务不能依赖进程内单锁替代双库一致性。
- [x] 产生过任何库存流水后，商品类型和基本单位永久禁止修改；商品维护 UI 明确提示，直接调用 API 同样拒绝，名称、型号等描述仍可编辑。
- [x] 商品字段修改与首次过账竞争也遵守身份锁定和单位一致规则，不只做一次事务外历史查询；无流水商品仍保留 Phase 2 修改能力。
- [x] 公开行为覆盖过账/编辑/取消草稿竞争、三位小数运算、超范围求和或取反、停用/单位变化、首次入库、并发扣减、快照和审计回滚；余额与原始流水累计一致。
- [x] POSTED 内容锁定，状态详情区分未过账与已过账；本任务不开放已过账取消，冲销由后续任务增加。
- [x] 沿用现有登录认证和已登录账号访问范围，记录实际操作人；真实菜单按现有角色菜单规则接入，不使用 mock 权限充当后端授权。
- [x] 业务修改和操作审计同事务，失败整体回滚；如新增 schema/seed，使用双库逻辑版本同步的 Goose 迁移，不改写旧版本。
- [x] 公开 HTTP 行为和真实数据库验证在 PostgreSQL/文件型 SQLite 上通过；新增 contract 确实被现有数据库门禁选中，跳过与未执行项如实报告。
- [x] API 源注解与 Swagger 重新生成，实际页面路径可演示；执行后端 tests+vet、前端 lint/build 及与改动对应的双库检查，报告结果。
