# 11：采购退货过账、金额尾差与逆序取消

**GitHub issue:** [#25](https://github.com/EziosWJ/simple-inventory/issues/25) · `ready-for-agent`

## Parent

Phase 4 规格：https://github.com/EziosWJ/simple-inventory/issues/14

## What to build

经营者核对采购退货草稿，整单扣库存、减少供应商总欠款或形成待收退款；分次退货额度和金额准确，录错时按原明细逆序取消。

## Acceptance criteria

- [ ] 最新版本整单过账，事务内锁定原 POSTED 单及稳定原明细额度；并发/重复不超退，同商品不同价的额度不能互换。
- [ ] 按商品合计扣共享库存，任一不足整单拒绝；增加原明细累计生效退货数量，并以原商品快照/单位/价记录真实退货来源。
- [ ] 本次行金额按累计退量×原价取整减既有金额，全部退完累计等于原行金额；零金额仍写实物流水，算术溢出整单拒绝。
- [ ] 减供应商方向总余额，先减欠款、超出部分待收退款；本任务不执行实际退款，不自动改变客户方向。
- [ ] 库存、往来流水/余额、单据状态、额度和审计同事务，审计/任意写入失败完整回滚；当前库存/流水可追溯采购退货来源。
- [ ] 本任务同时将生效退货阻塞接入原采购取消；已取消退货不占用额度，原采购可在无其他生效退货且满足约束时取消。
- [ ] 取消仅允许每个原明细的最新仍生效退货，多行任一非最新则整单拒绝；反向原数量/原金额、恢复额度、不重算历史，不级联删改既有资金记录；实际供应商退款后取消的公开回归由后续退款任务贯通。
- [ ] 重复过账/取消防重，原单取消竞争/多退货并发与额度恢复一致；停用历史退货仍可处理。
- [ ] 双库公开行为覆盖同价/不同价分行、累计尾差/零金额、跨原单拒绝、并发超退、逆序取消、审计回滚及原单阻塞，余额与流水累计一致。
- [ ] 沿用 JWT 和已登录账号业务范围，实际菜单按角色接入并授予 ADMIN，拒绝未登录请求；不以 mock 权限替代后端认证。
- [ ] 所需 schema/seed 使用 PostgreSQL/SQLite 逻辑版本同步的增量 Goose 迁移，不改旧版本、不用 AutoMigrate；保持现有业务数据与 API 兼容。
- [ ] 本任务业务维护与操作审计同事务，错误明确且保留表单输入；新增/修改 REST API 源注解与 Swagger 重新生成同步。
- [ ] 以公开 HTTP 和真实双库验证本任务行为，新增 contract 名含 Postgres/SQLite 并确实被门禁执行；相关后端 tests/vet、前端 lint/build 和数据库检查完成，报告失败、跳过和未执行项。
