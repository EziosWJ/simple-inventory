# 01：库存调整单草稿建档、详情和分页查询

**GitHub issue:** [#8](https://github.com/EziosWJ/simple-inventory/issues/8) · `ready-for-agent`

## Parent

Phase 3 库存基础规格：https://github.com/EziosWJ/simple-inventory/issues/7

## What to build

经营者可从真实业务菜单建立包含多种实物商品的库存调整草稿，逐行填写增减数量、原因和说明，保存后按单号、状态、商品及创建时间查询并查看详情。本任务交付可独立演示的草稿建档查询路径，保存不改变库存。

## Acceptance criteria

- [x] 建立库存调整业务入口，支持新建、草稿详情和分页查询；新单仅保存为 DRAFT，不生成库存余额或流水。
- [x] 系统自动生成唯一不可修改的单号，编码碰撞或并发建档不能覆盖旧记录；本任务定义单据版本和状态返回契约，供后续编辑、过账、取消复用。
- [x] 每单至少一行，同一商品只能出现一次，只允许选择启用实物商品；服务和停用商品在界面与后端均被拒绝。
- [x] 明细保存商品内部 ID、用户确认的类型与单位、非零增减数量、原因、说明；允许不同商品有不同增减方向。
- [x] 数量最多三位小数，API 十进制字符串准确往返，持久化采用适当定点方案；零值、无效输入、超精度及存储溢出被拒绝，不使用 float。
- [x] 原因逐行选择：期初录入/盘盈只增，盘亏/报损只减，其他可增减但说明必填；采用稳定业务编码校验，可复用现有字典展示。
- [x] 按单号、状态、商品、创建时间筛选，沿用现有分页响应和稳定排序，筛选多明细单不重复计数；详情显示创建操作人、时间与全部明细。
- [x] 表单错误明确并保留输入；已保存单号和版本可再次获取，创建记录和审计原子提交，审计失败不留单据或明细。
- [x] 验证并发建档唯一性、三位小数、同商品重复、原因方向、空说明、未登录拒绝、分页总数与筛选；双库空库和 Phase 2 增量迁移通过。
- [x] 本任务不开放编辑、过账、取消或删除接口；已保存草稿由后续任务维护，不提前增加库存字段或业务流水。
- [x] 沿用现有登录认证和已登录账号访问范围，记录实际操作人；真实菜单按现有角色菜单规则接入，不使用 mock 权限充当后端授权。
- [x] 业务修改和操作审计同事务，失败整体回滚；如新增 schema/seed，使用双库逻辑版本同步的 Goose 迁移，不改写旧版本。
- [x] 公开 HTTP 行为和真实数据库验证在 PostgreSQL/文件型 SQLite 上通过；新增 contract 确实被现有数据库门禁选中，跳过与未执行项如实报告。
- [x] API 源注解与 Swagger 重新生成，实际页面路径可演示；执行后端 tests+vet、前端 lint/build 及与改动对应的双库检查，报告结果。
