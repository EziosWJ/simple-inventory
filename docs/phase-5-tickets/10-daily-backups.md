# 10：每日整套备份、30 天保留与异地复制步骤

**GitHub issue:** [#49](https://github.com/EziosWJ/simple-inventory/issues/49) · `ready-for-agent`

## Parent

[Phase 5 规格 #39](https://github.com/EziosWJ/simple-inventory/issues/39)

## What to build

生产部署包每天自动生成数据库、上传文件和必要配置的一致备份，识别成功或失败，保留 30 天并可按说明复制到另一设备或存储。

## Acceptance criteria

- [ ] 每日调度及手动触发共用同一备份流程，执行时间/时区明确，使用匹配 PostgreSQL 主版本的逻辑备份工具。
- [ ] 归档数据库、上传文件、必要配置、应用/迁移版本及校验信息；采用可验证维护窗口或暂停业务写入取得一致集合。
- [ ] 整套成功并基本校验后才标记成功；失败为非零结果并有可查日志，半份产物不视为备份，失败后恢复业务运行条件。
- [ ] 重复或重叠触发不损坏备份；任务重试不覆盖最近成功备份，机密配置及备份访问权限受控。
- [ ] 只清理本部署备份目录中明确归属且超过 30 天的成功完整备份，不删除源库、上传目录、配置、不明文件及最近可用备份。
- [ ] 提供异地复制与完整性核对步骤，不自动绑定外部账号/存储；说明每日频率最多约一天补录及尚未异地复制的恢复边界。
- [ ] 在隔离部署实际执行成功及失败路径并验证归档内容、校验、权限、重复运行和保留范围；验证调度确实配置而非仅有文档。
- [ ] 本任务完成备份生成和调度的可验证闭环，实际恢复及回退由后续任务承接。
