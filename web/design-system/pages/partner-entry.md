# 收付款、退款和期初往来

采用 Standard List Page；短登记流程使用 FormDialog，详情使用 DetailDialog，不新增页面模式。

- 默认显示筛选与记录列表，页头分别提供客户和供应商方向的登记按钮。登记表单不常驻页面，弹窗中不再重复选择方向。
- 从往来余额或退货带入 partnerId / direction 时自动打开对应登记弹窗；带 entryId 时打开记录详情。
- 填写顺序为对象、当前欠款或待退款、实际金额、登记后结果、日期和方式。备注、交易号、附件默认折叠；附件失败摘要保持可见。
- 当前往来使用浅蓝背景摘要区，含义与金额分行，金额以 30px 加粗和千位分隔表达。查看往来明细在同一弹窗内按需拉取全部业务，支持分页、错误重试与收起，保留登记输入；切换单位或方向清空旧明细。
- 核对与填写复用同一个弹窗，返回填写保留内容；保存成功关闭弹窗并回到列表，失败保留输入、附件及请求键，更新余额后重新核对。
- 表单宽度上限 680px，复用公共弹窗固定头尾、正文滚动能力。单位浏览窗口和放弃确认打开时，父表单暂停焦点圈定与 Escape 响应。
- 金额使用正金额和业务含义表达。历史记录的前后余额标明是本笔生效时的余额，成功回执保留本笔登记后的快照。
- 期初记录查询仅用 OPENING / EFFECTIVE 的实际结果提醒重复补记，不把所有往来记录数当作期初笔数。
- 原记录与冲销记录可互相追溯；冲销前显示当前余额与预计结果，实际结果仍以服务端事务校验为准。冲销记录不提供再次冲销或附件补传。

专项验收入口：`node tests/partner-entry-workflow.mjs`、`node tests/partner-attachments.mjs`。两者拦截 API，不代表真实数据库事务验收。
