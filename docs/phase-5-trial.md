# Phase 5 两名经营者试用记录

**状态：待人工，尚未邀请或记录父母实际试用。** 自动技术验收通过不等于两位已经会用，也不代表正式上线获准。试用仅在隔离环境，使用代表性虚构单据，不修改真实店铺数据。

维护者先按部署说明启动已验收版本、准备两名独立账号及打印机/PDF，告知试用地址并当面提供各自密码。先建几件常见同名不同型号商品、一个服务项目，以及同时有客户/供应商身份的往来单位；准备少量可售库存。两位各用自己的电脑浏览器或独立浏览器会话，不共用账号。试用结束后备份试用库并停止隔离服务。

| 场景 | 两位各自完成的动作 | 需要观察的结果 | 父亲结果 | 母亲结果 |
| --- | --- | --- | --- | --- |
| 独立登录与入口 | 登录后从首页找到开采购、开销售、查欠款、查单据 | 不依赖维护者指出按钮；看见共同业务 | 待试用 | 待试用 |
| 找商品/往来 | 输入编码、部分名称、型号或电话，翻页选同名正确记录 | 能辨认型号/单位/联系方式，不误选另一档案 | 待试用 | 待试用 |
| 采购草稿 | 普通采购两行，其中同商品不同价格；核对合计后保存 | 草稿有单号，未增加库存/欠供应商金额 | 待试用 | 待试用 |
| 离开与修改 | 修改未保存数量，再尝试离开，取消离开后继续 | 提醒可理解，输入仍在；不误以为已保存 | 待试用 | 待试用 |
| 双人接力 | 一位保存，另一位找到同一草稿并核对后过账 | 原单 ID/单号保留，实际过账人正确，共享库存/应付 | 待试用 | 待试用 |
| 双人冲突 | 同开一张草稿，先后保存不同数量，再确认重新加载 | 旧版本拒绝保留输入；知道加载最新会丢弃自己的未保存修改 | 待试用 | 待试用 |
| 销售与送货 | 实物加维修服务，核对送货资料、价格和应收后过账 | 实物扣库存，服务不动库存；同一已保存送货单可打印 | 待试用 | 待试用 |
| 库存不足 | 尝试超过库存数量的销售，再改回可用数量 | 留在原草稿继续修改，不需要再新建一单 | 待试用 | 待试用 |
| 直送 | 从直送采购关联销售，先采购后销售分别过账 | 知道各自确认金额；不增加/扣减店内库存；返回来源清楚 | 待试用 | 待试用 |
| 查单据 | 组合对象、商品、日期、状态，翻页看详情再返回/刷新 | 条件和页码保留；停用资料旧单仍可找到 | 待试用 | 待试用 |
| 查欠款/往来 | 同一对象分别看客户/供应商余额，再选期间和来源 | 两个方向不抵扣；正欠款和负待退款可理解；追溯原单并返回 | 待试用 | 待试用 |
| 打印核对 | 送货金额显隐、草稿标记、签收；完整期间对账 | 合计、页码、历史资料清楚，多页不丢行；能保存 PDF | 待试用 | 待试用 |
| 异常结果说明 | 由维护者在隔离环境演示响应丢失后的结果核实 | 明白先核实原单，再决定是否重试；不急着新建重复单 | 待试用 | 待试用 |

每个场景分别记为“独立完成 / 提示后完成 / 未完成”，记录耗时和最先卡住的操作。维护者不提前代填答案；发生困难可当面描述或记录截图，截图避开密码和无关资料。记录格式：

```text
日期 / 版本：
试用者 / 场景：
结果：独立完成 / 提示后完成 / 未完成
卡住时正在做什么：
预期是什么 / 实际看到什么：
需要多少提示：
关联测试单号（如有）：
后续修正任务：T01–T12 / 新范围另行评估
```

父母反馈后先修正影响录单、查账或理解状态的对应任务，再复验并重新试用。正式服务器、真实证书、业务迁入、异地备份目的地及上线决定仍按后续安排处理；本记录不替代这些步骤。
