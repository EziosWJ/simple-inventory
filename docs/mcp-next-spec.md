# MCP 后续实施规格

状态：2026-10-15，Q1～Q14 产品决定已确认，本规格已实现并通过验证；实施与验证结果见[实施进度与验证记录](mcp-next-progress.md)，使用方法见[使用说明](mcp-usage.md)。讨论记录见[需求讨论](mcp-next-plan.md)，架构取舍见[ADR-0017](adr/0017-recoverable-mcp-tokens-and-inherited-query-permissions.md)。

## 1. 目标与范围

保留现有HTTP、Cloudflare Tunnel、进程内官方Go SDK Streamable HTTP入口。在正常 `task dev:sqlite` 和现有业务库上使用，实现：

1. 后台管理员管理MCP令牌，随时查看、复制，选择有效期并延期。
2. 客户端使用 `token: <原值>`，旧Bearer客户端继续可用。
3. 新增采购／销售明细、单据详情、往来明细及对账查询。
4. 按用户要求开放参考价、联系方式、地址、开票资料、税号、银行账号和备注。

继续仅提供业务只读工具。本轮不增加库存变动追溯、经营排行、利润／成本报表或业务写工具。仅统计完整查询范围的业务合计，不从单页结果推断全量。

## 2. 后台令牌管理

入口放在系统管理的“MCP令牌”，由管理员统一管理，绑定已有系统用户。沿用现有RBAC机制，新增菜单权限 `system:mcp-token`，默认赋予内置管理员；MCP管理API显式校验此权限，不能只隐藏前端按钮。新增管理权限不提升绑定用户的业务权限，不扩展为全仓鉴权改造。

一个用户可有多枚令牌，以名称区分电脑、手机等，也可多个客户端共用一枚。令牌系统生成，保持现有随机强度；创建只需名称、绑定用户和有效期，不填写client ID或逐工具scope。

列表显示名称、绑定用户、启用状态、有效期、是否支持查看及管理操作。原值默认遮罩，点击查看／复制时获取原值；创建、延期、启用／停用、重置即时生效，不要求重启API。复制同时兼顾本地HTTP和Tunnel HTTPS，不额外要求用户搭建环境。

### 有效期和状态

- 默认永久，数据库以空到期时间表达；可选择7／30／90天或自定义未来日期。日期选择按Asia/Shanghai解释，具体到期时刻在页面明确显示。
- 延期保留原值。未过期从原到期时间增加，已过期从当前时间增加；也可改为永久。
- 停用／启用独立于有效期。停用后请求失败；延期不自动启用；启用仍要求未过期、绑定用户有效且有业务权限。
- 重置只替换原值、摘要和密文，旧值立即失效；保留绑定用户、名称、有效期及启用状态。已过期或停用的记录不会因重置悄悄恢复可用。
- 永久令牌无需按天延期；可以编辑为有期限。

### 保存、旧令牌和CLI

- 继续保存SHA-256认证摘要，新令牌另存版本化AES-GCM密文及随机nonce。认证仍只使用摘要，不需要先解密。
- 使用现有 `jwt.secret` 经独立用途派生显示加密密钥，不增加启动参数或外部服务；不得直接当成未分离用途的通用密钥使用。
- 列表不返回密文、摘要或原值；管理员专用查看接口解密并返回 `Cache-Control: no-store`。授权依赖现有登录和管理权限，不增加二次密码或审批流程。
- 密钥缺失／改变导致无法解密时，明确提示恢复原配置或重置，不错误声称令牌不存在。摘要认证仍可继续有效。
- 备份恢复沿用数据库及同批配置一起保存的规则；密钥更换后的影响写入使用说明。
- 旧摘要令牌、原到期时间与停用／吊销状态保留。旧值不能还原，标记“旧版令牌，重置后可查看”；不强制批量失效。
- 所有有效旧令牌也转为动态继承绑定用户当前业务权限，不要求重签。旧scope字段可为迁移兼容保留，但不能继续拦截新增查询。
- CLI保留管理兼容入口，默认有效期与后台统一，支持永久。原 `--scopes` 用法如保留，应明确提示已改为用户权限继承，不能显示“受限scope”造成误解。简化task仍可签发令牌。
- 管理动作记录操作者、目标用户、令牌ID、动作及有效期／状态变化；不记录原值或密文。

## 3. 客户端认证

新写法：

```text
token: <令牌原值>
```

兼容 `Authorization: Bearer <令牌原值>`。请求头名称不区分大小写；不增加tk别名或URL凭证。两种写法同时提交且原值相同可接受，不同时返回明确参数错误，不静默选择其中一个。重复或格式非法的凭证头拒绝。

每个HTTP请求、工具列表和工具执行均检查当前令牌、用户及角色菜单授权。仅允许本系统登记的只读工具；scope不再由管理员逐枚勾选。工具列表与调用授权一致，撤权、停用、过期和重置后下次请求生效。

沿用Host配置、Origin检查、请求与输出限制，允许Tunnel正常转发头；不重新引入仅回环访问限制。

## 5. 查询输入与日期

- 搜索／列表支持页码、每页条数，默认20、最多50，页码最多1000。拒绝未知字段、非法ID／枚举／日期和前后倒置的区间。
- 商品／单位继续保留同名候选，不能擅自选择第一项。库存、余额、单据详情、单位对账使用准确内部ID。
- 采购／销售明细支持日期、商品、客户／供应商、单号及状态；不指定对象可查所选期间全店明细。
- 采购／销售默认POSTED，支持明确指定DRAFT、CANCELLED或ALL；ALL时按状态分别表达合计，不混作有效业务。
- 往来明细支持日期、单位、方向和业务类别；单位可省略。对账必须指定单位，方向可省略。
- 带期间的新增查询未给日期时默认本月，按Asia/Shanghai的月初至月末处理；部分给日期时必须补齐另一端，不暗猜完整期间。
- 采购／销售按原业务日期筛选，起止日均含。往来明细及对账沿用实际生效时刻口径，将上海日期转换为起始日零点至结束日次日零点的左闭右开区间，另外展示原业务日期。
- 响应明确返回实际filtersApplied、timeZone、timeBasis及查询时刻。模型将“上个月”等问题转换为明确日期，不能让业务数据中的文本改变查询规则。
- 当前库存与当前余额不应用本月默认范围，继续只表示当前状态。

## 6. 字段与金额语义

### 当前档案与历史数据

商品对象可返回编码、名称、类型、品牌、型号、规格、分类、单位、状态、参考采购价、参考销售价和备注。参考价保持业务十进制字符串及空值，不能解释为历史成交价或库存成本。

往来对象可返回编码、名称、类型、双身份、状态、联系人、电话、地址、开票抬头、税号、注册地址／电话、开户行、银行账号和备注。此类信息来自当前档案；银行账号不能描述为某笔历史付款实际使用的账户。

单据详情返回单据和行备注、实际成交价与金额。已过账商品描述与基本计量单位使用单据快照；销售客户名称与送货资料使用冻结快照，包括当时空值。采购供应商名称沿用Service返回的当前档案名称，不虚构供应商名称快照；不以当前资料覆盖已有历史快照。当前参考价／联系／银行资料如补充返回，放在明确标记的当前档案对象中。

往来记录返回类型、单位、方向、业务日期、生效时间、来源单据、带符号金额、前后余额、人工摘要／资金备注／冲销原因，以及已有支付方式、交易流水号和冲销关系。交易流水号不等于银行账号。

继续采用显式业务DTO控制字段语义，调整首版字段清单以包含以上内容；不会以序列化原始模型代替精确投影。业务文本按现有字段长度完整返回，不沿用首版统一截取200字符的方式截断500字备注；超出整体输出限制则明确报错。

### 退货、净额与往来

- 数量、单价与金额沿用业务Service的十进制字符串，不用浮点数重新计算。
- 采购／销售同时表达原始、截至当前有效退货、净数量／净额。9月销售的10件在10月有效退回2件，之后查9月得到原始10、有效退货2、净8。
- 只计仍已过账且未取消的有效退货；草稿、取消单、服务不可退货等适用性沿用原业务规则，不能用0冒充“不适用”。
- 汇总覆盖完整筛选范围，按状态分别给金额，按商品和单位分别给数量，不能混加不同商品或计量单位。
- 往来记录保留原始和反向冲销，不能删掉已冲销原记录后计算对账。期初、期间增加／减少、净变化与期末来自同一业务口径。
- 客户正余额为客户欠经营者，负余额为经营者应退客户；供应商正余额为经营者欠供应商，负余额为供应商应退经营者。
- 双身份未选方向时分别返回现有或历史有效方向，不自动抵扣。不具有所选方向且无历史记录时明确说明，不杜撰另一方向金额。
- 无记录与有记录但零余额分别表达；余额不解释成单张单据未结金额。

## 7. 分页、输出与错误

保留64KiB请求体、10秒查询超时、单令牌每分钟60次、全局并发4和单请求单RPC。因完整业务字段增加，将默认输出上限调整为512KiB，配置仍有明确上界；不靠静默删除备注或银行资料满足大小限制。

明细与对账行都分页，详情内的行也可分页；头部／对账摘要及总数明确表示完整对象或完整期间，不能仅计算当前页。必要时补充领域Service的数据库分页或有界读取，尤其处理当前往来明细内存分页及Statement一次返回全部记录的实现。不得为此改动金额、过账、冲销或历史快照规则。

输出仍超限时明确要求缩小范围，不返回貌似完整的部分结果。区分未认证、无权限、非法参数、对象不存在、无记录、超时与暂时不可用；错误不输出数据库内部信息。访问日志保留工具、主体、耗时、状态和记录数，不增加令牌或业务结果全文。

## 9. 验收要求

- 凭证：永久、可选期限、延期起点、过期恢复、停用延期不启用、重置旧值立即失效、多枚／共用、用户撤权／停用即时生效。
- 管理：仅管理员权限可管理／查看，列表遮罩、点击复制、错误密钥明确提示、密文认证独立、管理审计不含原值。
- 兼容：旧摘要继续有效且标记不可查看，重置后可看；旧Bearer、token、相同／冲突双凭证及畸形重复头；旧scope统一按当前用户权限处理。
- 查询：同名候选、本月／自定义日期、Shanghai边界、业务日期与生效时刻、已过账默认与草稿／取消、全筛选集合计、期后退货净额、对账双方向及冲销、分页／超限。
- 字段：实际成交价与参考价分别准确；联系／开票／银行资料和备注可返回；当前银行资料不冒充历史付款账号，历史快照空值不回填当前资料。
- 网络：正常开发task、本机HTTP、手机／Tunnel HTTPS；转发头和回环来源＋外部Host继续可用。
- 按仓库要求先定向SQLite、再定向PostgreSQL；涉及schema，收尾一次 `task db:check`，另验双库空库、旧版本升级及迁移断言。新增契约须被Taskfile／CI实际各选中一次，无匹配或SKIP不算通过。
- 本轮新增管理REST，须运行 `task api:docs` 并核对；本轮新增前端，须运行lint/build及相关页面测试。复用仍匹配当前代码的检查，不以无关全量检查替代行为验收。

日常使用仍是 `task dev:sqlite`，在后台管理凭证并复制到客户端；不增加独立试用库或额外部署服务。旧CLI保留为可选管理方式。
