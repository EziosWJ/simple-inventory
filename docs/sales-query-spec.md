# 销售出库：单据内容、跨单明细查询与净销售合计

## Problem Statement

经营者在销售出库页面筛选数据时，操作按钮独占侧栏，挤压字段并形成大块空白。单据列表仅显示单号、客户、日期、状态和金额，了解销售内容必须逐单打开详情。

经营者需要直接回答“某客户这段时间买了什么、多少、什么价格”和“某商品卖给了谁、历史成交价是多少”。现有单据分页无法直接支持跨单明细分页和全部匹配明细的合计；只对当前页计算或使用整单金额会给出错误结果。退货、取消和服务还需要明确的表达，防止将原销售金额误解为当前净销售额。

## Solution

仅完善销售出库页面：筛选字段占用完整可用宽度，查询与重置在底部靠右，刷新位于列表工具栏。提供默认的“按单据”视图和可切换的“按明细”视图；单据直接展示内容摘要并可展开，明细跨单展示销售对象、数量、成交价、金额及退货后的净值。

沿用单号、客户、商品/服务、状态、业务日期组合查询，增加“本月”“已过账”快捷条件。明细提供全部匹配数据的状态分组金额合计和商品/单位数量合计。销售按原单业务日期选取，退货取截至当前仍有效的结果，明确标注口径；查看原单并返回后恢复查询上下文。用户体验确认后，再另行决定是否推广到其他页面。

## User Stories

1. As an 个体店铺经营者, I want 销售筛选字段使用面板完整宽度, so that 按钮侧栏不会挤压输入空间。
2. As an 个体店铺经营者, I want 查询与重置按钮在筛选面板底部靠右排列, so that 条件和操作容易找到。
3. As an 个体店铺经营者, I want 在列表工具栏刷新当前结果, so that 不必重新填写查询条件。
4. As an 个体店铺经营者, I want 按销售单号查询, so that 快速定位已保存单据。
5. As an 个体店铺经营者, I want 按客户和业务日期查询, so that 查看指定客户期间买过的商品和服务。
6. As an 个体店铺经营者, I want 按商品或服务查询, so that 查看销售对象及历史成交价格。
7. As an 个体店铺经营者, I want 组合客户、商品、日期和状态条件, so that 缩小查询范围。
8. As an 个体店铺经营者, I want 默认查询全部日期和状态, so that 不遗漏旧单、草稿和取消单。
9. As an 个体店铺经营者, I want 一键限定本月业务日期, so that 快速查看本月单据。
10. As an 个体店铺经营者, I want 一键限定已过账状态, so that 快速查看已生效销售。
11. As an 个体店铺经营者, I want 重置后回到默认查询条件, so that 重新开始检索。
12. As an 个体店铺经营者, I want 默认按单据浏览, so that 保持熟悉的销售查单流程。
13. As an 个体店铺经营者, I want 每张销售单直接显示内容摘要, so that 不打开详情也能辨认卖了什么。
14. As an 个体店铺经营者, I want 展开单据查看完整明细, so that 就地核对所有销售内容。
15. As an 个体店铺经营者, I want 商品筛选后的单据仍显示整单且突出匹配商品, so that 既看匹配内容也了解整单背景。
16. As an 个体店铺经营者, I want 切换到按明细浏览, so that 跨单查看客户、商品和历史成交价。
17. As an 个体店铺经营者, I want 按明细视图只显示匹配商品行, so that 不被同单其他商品干扰。
18. As an 个体店铺经营者, I want 切换视图时保留筛选条件, so that 比较相同业务范围的两种展示。
19. As an 个体店铺经营者, I want 明细显示业务日期和客户, so that 知道销售何时发生以及卖给谁。
20. As an 个体店铺经营者, I want 明细显示商品或服务名称及型号规格, so that 辨认不同销售对象。
21. As an 个体店铺经营者, I want 数量与基本单位一起展示, so that 正确理解支、台、次等不同计量。
22. As an 个体店铺经营者, I want 明细显示成交单价和原明细金额, so that 核对实际约定价格。
23. As an 个体店铺经营者, I want 同商品不同价格的原明细分别保留, so that 比较历史成交价而不丢失差异。
24. As an 个体店铺经营者, I want 明细显示来源单号和状态, so that 区分草稿、已过账及已取消内容并找到原单。
25. As an 个体店铺经营者, I want 从明细打开原单, so that 查看完整业务及使用已有单据操作。

35. As an 个体店铺经营者, I want 明细金额合计覆盖全部筛选结果, so that 翻页不改变对所选业务范围的判断。
36. As an 个体店铺经营者, I want 草稿、已过账和已取消金额分别统计, so that 分清不同状态的内容。
37. As an 个体店铺经营者, I want 数量按商品及单位分别合计, so that 不混加不同商品或不同单位。
38. As an 个体店铺经营者, I want 商品筛选的合计只包含匹配明细, so that 不把同单其他商品金额算入。

43. As an 个体店铺经营者, I want 默认按业务日期从新到旧且排序稳定, so that 优先查看近期销售并可靠翻页。
44. As an 个体店铺经营者, I want 明细按成交单价、原金额或净额升降序排列, so that 比较价格和金额。

46. As an 个体店铺经营者, I want 应用筛选、切换视图或排序时回到第一页, so that 不因旧页码看到错误空页。

## Implementation Decisions

### 1. 模块与兼容边界

- 修改销售出库展示与销售查询能力；复用商品、往来单位历史选择、单据详情和查询上下文能力。公用搜索组件可以通过显式选择的布局能力支持销售，但默认行为不变；其他页面不推广本次布局。
- 保持 Handler → Service → Repository 边界。Service 不依赖 Gin Context、GORM 或具体数据库；双库差异局部化于数据库或 Repository。
- 现有单据分页已经返回销售明细，可用于单据摘要与展开。跨单明细分页、退货结果和全范围合计由服务端查询提供，不能拉取有限单据页后假装全量。
- 本批是既有销售能力上的查询扩展，不改变业务写入、库存、往来、审计及状态转换。默认复用已有存储；确需 schema 或索引变更时使用双库 Goose migration，禁止 AutoMigrate。

### 2. 筛选与单据展示

- 保留单号、客户 ID 或关键词、商品 ID 或关键词、状态、业务日期起止条件，沿用现有组合匹配规则与历史资料检索范围；界面继续说明当前档案与历史快照检索差别。
- 本月以应用既有业务日历口径设置当月起止日期；已过账快捷条件只设置状态，保留其他条件。日期端点包含所选日，起止反向时明确提示。刷新重查当前已应用条件，重置恢复全部日期及状态并回第一页。
- 筛选字段使用完整可用宽度、按可用空间排列；查询和重置在底部靠右，刷新移至列表工具栏。摘要在空间受限时可缩略，但展开必须显示整单全部明细。
- 按单据的分页总数是单据数，匹配多条商品明细不能重复计数。保留单号、客户、业务日期、状态、整单金额与原有动作；商品筛选仍展示整单，匹配行突出显示，整单金额明确区别于匹配明细金额。

### 3. 跨单明细查询契约

- 提供销售明细分页与全结果汇总的只读查询能力，继承既有认证和销售查询权限。接口名称与具体路由在实现时按现有业务接口惯例确定，旧单据分页行为保持兼容。
- 请求包含既有筛选条件、page、pageSize、排序字段和方向。仅允许约定排序字段，参数无效时明确校验错误，不能将用户文本直接拼接为 SQL 排序。页面提供 10/20/50，API 按既有分页上限校验。
- 每条记录对应一条原销售明细，带有唯一明细身份、来源销售身份及单号、客户身份和历史名称、业务日期、销售状态、商品身份和历史描述、类型及单位、数量、成交单价、原明细金额、有效退货数量/金额、净数量/净额及适用性。
- 返回 records、total、page、pageSize，并提供同筛选范围的金额汇总与商品/单位数量汇总。total 是匹配原销售明细数。汇总不受页码、每页条数和排序影响；没有结果时记录为空、总数为零、金额为零且数量分组为空。
- 商品 ID 只匹配其明细；关键词按既有商品查询范围逐明细判断，不能将匹配整单的其他商品行混入结果或合计。客户和单号等单据条件限制来源单据。
- 退货先按原明细汇总，再与销售关联；多笔退货不能倍增原数量、原金额或总条数。同商品不同价格原明细保持独立。
- 默认业务日期降序，同日以稳定单据身份及明细顺序消除排序并列。单价、原金额和净额升降序同样有稳定并列顺序；数字按精确值排序，不能按字符串字典序。草稿及取消单的净值不适用，应与有效值明确区分并稳定排序。
- 列表、总数和汇总使用同一组条件与当前有效退货口径；并发过账、退货或取消不得让同一次查询重复读出互相矛盾的数据。采用双库支持的一致读取方式，不改变写入事务规则。

### 4. 退货、金额和数量

- 有效退货为截至查询当前状态仍 POSTED 的销售退货，按原销售明细关联。草稿和 CANCELLED 退货均不抵减。退货金额沿用已保存行金额，不能用参考价替代。
- 对 POSTED 销售，净销售数量＝原数量－有效已退数量，净销售额＝原金额－有效退货金额；无退货实物有效退货为零。服务退货列标记不适用，净数量与净额等于原值。
- 对 DRAFT/CANCELLED 销售保留原数量和金额供查询，有效净值标记不适用，不能将其原值计入有效净销售合计。
- 金额原值分别按 DRAFT、POSTED、CANCELLED 汇总，并明确标签；有效退货及净额只汇总 POSTED 来源销售。数量按商品 ID、快照单位及状态分组展示，不跨商品或单位混加，不因名称变化拆成不同商品身份。
- 展示单价与金额保留人民币两位小数，数量沿用现有精度；计算与排序使用精确 decimal/定点方案，不能以浮点近似合计。金额求和使用原行金额，避免先汇总数量再乘价格造成舍入或不同价格混算。
- 日期条件选择原销售的业务日期，不限制关联退货发生日期。9 月售出 10 支、100 元，10 月有效退回 2 支、20 元，当前查询 9 月得到原值 10 支/100 元、有效退货 2 支/20 元、净值 8 支/80 元；取消该退货后净值恢复 10 支/100 元。
- 标注“按销售业务日期筛选，扣除截至当前有效退货”。历史期间净值允许随后续有效退货变化；不能称为期间固定结账结果、同期间销售减退货发生额、收款或利润。

### 5. 历史资料与交互

- 已过账单据沿用冻结客户及商品快照，包含当时为空的字段；草稿展示已保存内容，不用当前档案补造旧资料。同一商品按内部 ID 关联和汇总，历史名称用作描述，不作为身份键。
- 默认按单据；切换视图保留筛选与每页设置并回第一页。各视图按对应粒度维护页码及适用排序，应用筛选、排序和每页设置变化后回第一页。
- 明细表保留业务日期、客户、商品/服务、型号/规格、数量及单位、单价、金额、来源单号、状态，并增加退货和净值表达。内容较多时可合理分组或在表格内横向滚动，字段不能因截断不可访问。
- 全结果汇总展示在明细视图，数量分组过多时可折叠或独立滚动，但必须能查看所有分组，不能静默截取前若干项。
- 查看原单再返回，恢复视图、应用条件、排序、每页设置与页码。编辑、过账、取消等动作沿用原单能力，明细行不新增业务写入流程。
- 加载、失败、空结果要覆盖列表和合计，避免旧合计搭配新列表。过期响应不得覆盖新的查询；失败保留条件并提供重试入口。

## Testing Decisions

- 优先复用两个已有外部入口：真实浏览器中的销售页面，以及应用 HTTP 接口的双库集成契约。浏览器验证用户完整路径，HTTP 契约验证同一查询规则在 SQLite/PostgreSQL 上一致。无需为本次功能引入新的业务层或大量私有方法测试入口。
- 已有先例是 Phase 5 单据查询的真实浏览器验收及 HTTP 契约：覆盖同名对象、历史停用、商品多行去重、日期组合筛选、分页、详情/编辑返回和迟到响应；销售退货过账双库契约可复用有效退货、取消和原明细关联场景。
- 好的测试只断言用户可见内容、交互结果、HTTP 返回与业务持久状态，不依赖组件层级、内部函数、SQL 文本或具体布局类名。查询测试不得改变库存与往来数据。
- 浏览器覆盖常用电脑宽度下无按钮专属空白侧栏，字段清晰可用；单据摘要与整单展开；客户/商品两条查询路径；商品匹配突出与明细只显示匹配行；快捷条件、重置、排序、每页选择、分页、详情返回以及加载失败/迟到响应。
- 超过一页的夹具包含多个商品、单位、客户、同商品不同价格、同日多单、混合服务、纯服务、零价实物、草稿、已过账及取消。验证不同分页和排序下合计不变，匹配明细金额不包含整单其他行，金额数值排序正确，小数数量和舍入准确。
- 双库核对多次部分退货、跨月退货、草稿退货、退货取消，以及同商品不同价明细各自退货；防止退货 JOIN 放大原值和重复计数。验证 Q10 示例、服务不适用、草稿/取消不进入有效净合计。
- 历史场景覆盖客户/商品改名、停用、身份变化与空型号/规格，核对快照、ID 关联和分组。空结果及非法日期、排序、分页参数有明确行为。
- 实现时先运行最小相关 SQLite 检查，再验证 PostgreSQL；最终运行数据库兼容门禁（已包含后端检查），补前端 lint/build。新增双库契约分别使用 TestSQLite/TestPostgres 前缀，并核对 Taskfile 和 CI 各选中一次。
- REST API 变更同步源注解并通过固定的 API 文档生成任务更新 Swagger；若 schema 发生变化，双库验证空库迁移与旧数据升级，同步版本及受影响断言。
- 最终交付记录实际检查结果、未执行项与经营者试用反馈；自动检查不替代用户查看销售页面实际效果。当前阶段仅编写及发布规格，没有执行上述实施验收。

## Out of Scope

- 将新布局或多维查询推广到采购、退货、库存、往来等其他页面。
- 客户/商品销售贡献排名、趋势图、补货建议、库存成本和毛利。
- 按退货业务日期计算的期间销售减退货发生额报表、历史截止日复原或固定结账报表。
- 根据总收付款推断逐单结清、逐单欠款或账龄。
- 筛选结果导出及专门报表打印；已有送货单打印继续可用。
- 手机适配、新增岗位权限体系、变更销售及退货业务状态流程、服务退费和新的业务写入能力。

## Further Notes

- 本规格承接本轮 Q1～Q13 已确认讨论；用户调用 to-spec 要求直接综合并发布，不继续需求访谈。先交付销售效果再决定通用化。
- 现有阶段曾暂缓经营报表，本规格只新增已确认的销售明细查询与合计，不重新纳入其他报表范围。
- 沿用领域术语“业务日期”“成交单价”“商品资料快照”“有效已退数量”“净销售数量”“净销售额”。收付款按往来单位总欠款记录，遵守 ADR-0013。
- 既有 Phase 5 单据查询需求提供兼容基线；本规格增加摘要、明细分页与合计，不将已有查单任务或其线上状态误认为本功能已交付。具体技术依赖在拆分任务时据实际实现核对。
- 本轮没有新的难以逆转架构取舍，不新增 ADR。
