# MCP 首批交付需求讨论

状态：2026-10-15 用户已确认全部推荐，需求访谈完成。四工具实现进度与自动验证见[实施验证记录](mcp-server-v1-verification.md)，试用入口见[使用指南](mcp-server-v1-usage.md)。本文件保留需求确认过程。用户后续补充允许本地手机通过局域网试用、监听 `0.0.0.0`，网络边界以更新后的实施规格和使用指南为准。以 [PR #91](https://github.com/EziosWJ/simple-inventory/pull/91) 的私有 MCP V1 设计草案为讨论基础；已收敛为[首批实施规格](mcp-server-v1-design.md)，讨论记录、规格与架构决策由该 PR 一并交付。

## 已确认的方向

2026-10-15，用户接受首轮建议，并授权选择简单且必要的首批场景，以便快速完成开发、测试和试用。

- 首个交付版本采用只读查询，创建草稿、过账、收付款、退款及冲销留待后续。
- 首先打通一个目标客户端：Cherry Studio（用户已于第二轮确认）。
- 首批访问身份绑定父亲的系统账号，凭证可以单独撤销；不另设与该用户脱离的共享业务身份。
- 首轮使用隔离环境和少量样例数据，通过三个场景及权限验收后，再安排真实业务数据接入。隔离环境使用独立凭证，不要求复制生产密码或令牌。
- 按现有业务规则返回数据，复用业务 Service，不以单页结果推算全量统计。

## 按简化要求选定的首批场景

| 场景 | 示例问题 | 最小可验收结果 |
| --- | --- | --- |
| 找商品 | “帮我找这个型号的硒鼓。” | 返回候选商品的 ID、编码、名称、型号、规格、单位和状态；多个候选时保留区分信息 |
| 查库存 | “这个商品现在还有多少？” | 针对准确的商品 ID 返回当前库存数量与单位；区分零库存、查无商品与查询失败；服务不作为实物库存解释 |
| 查指定往来单位当前余额 | “某客户还欠多少？”或“还欠某供应商多少钱？” | 先确定往来单位 ID，再按客户或供应商方向返回余额；正负余额按欠款或待退款分别说明，两方向不自动抵扣 |

用四个只读工具覆盖：`search_products`、`search_partners`、`get_inventory_balances`、`get_partner_balances`。字段与分页边界见首批实施规格。

相对 PR #91 的七个 P0 工具，首批暂缓 `query_sale_items`、`query_purchase_items`、`get_partner_statement`。同时暂缓全店统计、排名、库存流水与交易追溯。其余默认关闭、私有访问、身份授权、输出限制和调用记录等基础约束继续作为设计基线，不因减少工具数量而省略。

## 首轮代码核对

- 四个场景的数据来源可以复用 `product.Service.Page`、`partner.Service.Page`、`inventory.Service.BalancePage` 和 `receivable.Service.FilterBalances`，不需要为查询本身新增业务表。独立令牌若按 PR 草案持久化，仍涉及双库 migration。
- 库存查询默认只返回非零库存。按指定商品查库存时需显式使用 `stock=all`，以免把零库存解释为商品不存在。
- 往来查询保留带符号的余额和客户／供应商两个方向，MCP 输出需准确解释欠款及待退款。
- 现有业务 REST 登录认证不能替代 MCP 的工具 scope 和业务权限校验；适配层仍需单独实现参数约束、字段筛减与授权。
- 可复用的业务权限分别为：`search_products` → `business:product`，`search_partners` → `business:partner`，`get_inventory_balances` → `business:inventory-balance`，`get_partner_balances` → `business:partner-balance`。首版不需要另建 MCP 角色体系。
- `BalancePage` 的空列表可能表示商品不存在或对象为服务；往来余额空列表也可能表示单位没有指定方向身份或历史记录。不能仅凭空列表断言对象不存在，需要通过商品／往来单位查询确认身份。

## 第二轮已确认

- Q5：Cherry Studio。
- Q6：使用父亲的账号。
- Q7：按推荐，先在隔离环境使用少量样例数据验证，通过后再接入真实数据。
- Q8：接受同机试用，Cherry Studio 连接同机运行的隔离 API；首批使用回环地址，不开放公网访问。
- Q9：接受管理员命令行签发、列举和吊销 MCP 专用令牌；暂缓 Web 令牌管理页面。

### Cherry Studio 能力核对

- [官方 MCP 文档](https://www.cherryai.com/docs/en/advanced-basic/extensions/mcp/) 说明远程 MCP 支持 SSE 和 Streamable HTTP。
- [官方 v1.6.0 MCPService.ts](https://github.com/CherryHQ/cherry-studio/blob/v1.6.0/src/main/services/MCPService.ts#L189) 包含 `streamableHttp`、`baseUrl` 配置，并把 `server.headers` 合并到 SDK 请求头；可承载独立 Bearer 令牌。不据此断言任意旧版本均已支持。
- 同机回环或局域网 HTTP 的可用性仍需目标 Cherry Studio 实机连接验收；源码中没有额外 HTTPS 限制只构成可行性线索。

## 最后一轮已确认

- Q10（输出）：仅返回商品身份与规格、库存数量和单位、往来单位身份及两个方向当前余额；参考价格、联系方式、地址、税号、银行账号和备注暂不输出。
- Q11（对象确认）：搜索保留多个候选，不让模型自行把同名对象当成同一对象；查库存和余额只接收已确定的内部 ID。零库存与服务无库存区分，零余额、无往来记录与查无对象区分。
- Q12（授权与令牌）：权限取父亲账号现有有效业务权限与令牌工具 scope 的交集；专用令牌默认有效 30 天，明文仅在签发时输出一次，数据库存摘要，支持即时吊销，父亲账号停用即停止访问。
- Q13（验收与下一步）：先完成四工具在隔离实例的协议、权限、双库和样例场景验证，再由 Cherry Studio 实机试用。开发环境未安装或无法交互操作 Cherry Studio 时，先交付可复现配置与试用清单，不能把 SDK 客户端测试写成 Cherry Studio 实机验收通过。整体方案已确认，先整理正式规格，再进入实现。

专用令牌涉及双库 migration，实施验证按仓库规则执行一次 `task db:check`（已包含后端检查），并补 PostgreSQL／SQLite 空库及旧版本升级验证；迁移无需为了四个工具另增角色或菜单。只读输出也应覆盖同名候选、服务、零库存、无往来记录、正负及双方向余额、字段白名单，以及过期／吊销／禁用／撤权等失败场景。

## 技术默认值

以下承接 PR #91 作为首批默认值，不逐项展开产品访谈：官方 Go SDK、进程内 `/mcp` 接入、默认关闭、独立身份认证与工具白名单；默认每页 20 条，上限 50 条；请求体上限 64 KiB，查询超时 10 秒，单凭证每分钟 60 次请求；Origin 存在时精确白名单校验、请求 Host 校验、限制并发；记录工具名、主体、请求标识、状态、耗时和记录数，不记录令牌或查询结果全文。店铺金额沿用人民币，时区采用 Asia/Shanghai，四工具只查当前状态，不提供相对日期或期间统计。

具体 SDK 版本、协议协商、CLI 形态及父亲账号在隔离实例中的映射方式仍需实施前技术核对；不复用生产令牌或复制生产用户密码。
