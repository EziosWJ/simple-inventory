# 销售查询与经营数据展示需求讨论

状态：Q1～Q13 已确认。用户调用 to-spec 要求综合并发布，正式规格已发布为 [GitHub #66](https://github.com/EziosWJ/simple-inventory/issues/66)，本地见 [销售查询规格](sales-query-spec.md)；尚未开始业务实现。

## 用户提出的问题

- 销售出库搜索面板的操作按钮独占一列，产生大块空白并挤压筛选字段，需要优化布局。
- 销售出库列表仅展示单据信息，无法直接了解销售内容，必须逐单查看详情。
- 下一目标是从多个维度查询和展示业务数据，帮助经营者使用系统和做决策。

## 既有约束

- 沿用根目录 CONTEXT.md 的产品范围和领域术语。
- Phase 5 规格暂缓经营报表；本轮明确新增范围后再形成后续规格。
- 库存目前只记录数量，尚无库存成本核算，不能用参考采购价或同期采购金额计算毛利。
- 收付款按往来单位总余额记录，不分配到单据，不能据此推断逐单结清或逐单欠款。
- 草稿、过账、取消及退货对查询与统计的表达，需要在选定目标后进一步确认。

## 代码核查

- `web/src/components/common/search-filter-bar.tsx:17`：大屏使用横向 flex 布局，字段区伸展，操作区不收缩并独立占据侧栏，对应截图中的空白与字段挤压。
- `web/src/pages/business/sales.tsx`：当前销售列表未展示商品明细；分页查询已返回 `items`。后端见 `server/internal/sale/repository.go:708` 及 `:747`，列表内容改善可先复用已有数据；跨单明细分页与汇总能力仍需按后续需求评估。

## 第一轮：已回答

### Q1 首批要完成的经营查询

候选：A 按客户和期间查看卖了什么、数量和成交价；B 按商品查看卖给谁及历史成交价；C 按期间查看商品或客户的销售贡献与趋势；D 结合库存与历史销量辅助补货；E 其他具体场景。

建议：首批选择 A、B，并由用户确定是否把 C 纳入同一批。

用户确认：接受推荐 A、B，首批支持按客户与期间查看销售内容、数量和成交价，以及按商品查看客户与历史成交价。C、D 未纳入首批。

### Q2 首批业务覆盖范围

候选：A 以销售为首批；B 同时覆盖采购和销售；C 同时覆盖采购、销售、库存和往来。

建议：A，以销售形成可用的明细查询和汇总路径，再按实际需要扩展。

用户确认：接受推荐 A，先完善销售出库，查看实际效果后再决定后续扩展。

### Q3 搜索布局优化范围

候选：A 只优化销售出库；B 统一优化使用同类搜索面板的业务页面。

建议：B，筛选字段使用可用宽度，操作按钮按一行高度靠右排列，空间不足时换行，具体布局在核查组件后确定。

用户确认：选择 A，只调整销售出库；体验确认后再决定是否通用化修改。

## 第二轮：已回答

用户确认：Q4～Q6 全部接受推荐。

### Q4 列表的展示粒度

建议：销售出库提供“按单据”和“按明细”两种视图，默认按单据。单据行直接显示销售内容摘要，可展开查看全部明细；按明细视图每行是一条销售明细，可跨单查看同一商品的客户与成交价，并追溯原单。筛选条件在切换视图时保留。

### Q5 明细需要展示的信息

建议：展示业务日期、客户、商品/服务名称、型号/规格、数量与单位、成交单价、明细金额、来源单号和状态。同商品不同成交价的原明细分别展示。原单详情承载编辑、过账及取消等业务动作。

### Q6 默认查询范围

建议：默认全部业务日期与全部状态，延续现有单据查找用途；提供“本月”和“已过账”快捷条件，查看实际销售时可快速限定范围。明细沿用来源单据状态，草稿与取消明确标识；退货在下一轮单独确认表达方式。

## 第三轮：已回答

用户确认：Q7～Q9 全部接受推荐。

### Q7 商品筛选的明细范围

按单据视图展示完整单据并突出匹配商品；按明细视图只展示匹配行。客户、日期、状态等条件在两种视图中沿用。

### Q8 退货后的明细表达

展示原销售数量、有效已退数量、净销售数量，以及原金额、退货金额和净额。有效退货仅包含仍已过账的退货，取消退货不计入；服务退货标记不适用。

退货结果截至当前，以原销售明细为归属；不是同一期间销售发生额减退货发生额。具体跨期案例在 Q10 核对。

### Q9 筛选结果合计

按明细视图统计全部筛选结果，翻页不改变合计。金额按草稿、已过账、已取消分别表达；净销售额仅统计已过账销售扣除有效退货后的金额。数量按商品及单位分别合计，不跨商品混加。

## 第四轮：已回答

用户确认：Q10～Q13 全部接受推荐。

### Q10 跨期退货与服务、取消的表达

建议：按销售业务日期筛选。9 月销售 10 支、100 元，10 月退回 2 支、20 元；当前查询 9 月，原数量与金额仍为 10 支、100 元，已退为 2 支、20 元，净值为 8 支、80 元。合计明确标注“截至当前有效退货”，历史期间净值可因后续退货及退货取消而变化。服务无退货，净数量与净额等于原值；草稿、已取消单据不计入有效净销售合计，行上的有效净值标记不适用。

### Q11 历史名称与商品关联

建议：沿用历史快照展示客户、商品、型号/规格及单位；草稿展示已保存内容。按内部商品 ID 关联和汇总，改名后仍可追查旧销售，历史筛选可选择停用资料。原来为空的历史字段保留空值。

### Q12 排序与分页

建议：默认业务日期从新到旧，辅以稳定的单据及明细顺序；按明细可按成交单价、原明细金额和净额升降序排列。单据与明细分别分页；切换视图、应用筛选或排序时回到第一页，详情返回恢复原查询及页码。提供每页 10/20/50 条。

### Q13 导出与打印

建议：本批先交付页面查询与合计，保留已有送货单打印；筛选结果导出和专门报表打印另行安排，待经营者试用后确定格式。

## 完整需求基线

### 交付内容

1. 仅改善销售出库页面。筛选字段使用完整可用宽度，查询与重置按钮在底部靠右排列；刷新放在列表工具栏，不独占筛选侧栏。保留单号、客户、商品/服务、状态、业务日期起止组合筛选；新增本月与已过账快捷条件。默认全部日期与状态。
2. 提供按单据与按明细视图，默认按单据；单据显示销售内容摘要并可展开完整明细，匹配商品突出显示。按明细可跨单查看匹配商品的客户、数量、成交价与金额，追溯原单。
3. 明细展示原销售、有效退货、净销售的数量和金额。单位随数量展示，同商品不同成交价分别保留；服务无退货，净值等于原值。草稿、已取消单据有效净值不适用。
4. 明细合计覆盖全部匹配数据，金额与按商品/单位汇总的数量按状态分开表达；有效净销售合计只计已过账销售扣除其有效退货。不得把当前页数据当作全结果合计，也不得把整单金额当作商品筛选后的明细金额。
5. 业务日期用于选取销售明细，有效退货截至当前计算，包括销售期间之后发生的退货；取消退货后恢复净值。标注计算口径，历史快照与空值保持不变，按内部商品 ID 关联，不因改名而拆成无关商品。
6. 提供稳定排序、单价/原金额/净额排序、独立的单据与明细分页及每页 10/20/50 条选择；查询上下文在查看原单返回后恢复。

### 范围边界

- 采购、库存、往来等页面与公用搜索栏默认行为不因本次改动变化。
- 本批不新增客户或商品贡献趋势、补货决策、库存成本与毛利、逐单结清推断、筛选结果导出或专用报表打印。
- 本轮改动不改变原销售、退货、过账、取消及往来结算业务规则。
- 本批可扩展销售查询 API 来提供明细分页及全结果合计，保持双库与现有单据查询兼容；不预设需要 schema 变更。

### 验收场景

- 搜索栏没有按钮专属空白列，常用电脑宽度下筛选字段清晰可用；只在销售出库生效。
- 多商品、多价格、混合服务的单据无需逐单打开即可了解内容；商品筛选在单据视图显示整单、在明细视图只显示匹配行。
- 超过一页的销售明细验证总条数、排序、全结果金额与按商品/单位合计；更换页码不改变合计。
- 9 月销售、10 月部分退货、随后取消退货，分别核对原值、有效退货与净值；草稿、已取消销售、服务与零金额销售正确表达。
- 商品/客户改名、停用及历史空型号/规格，核对历史展示与身份关联；详情返回保留视图、筛选、排序与页码。
- 根据最终变更执行前端 lint/build；涉及后端及数据库查询时执行对应检查与 PostgreSQL/SQLite 验证，REST API 变更同步注解并生成文档。业务实现完成后报告实际执行与未执行项。
