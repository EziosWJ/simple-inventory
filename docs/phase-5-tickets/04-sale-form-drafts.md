# 04：销售完整录单页、搜索与可靠草稿保存

**GitHub issue:** [#43](https://github.com/EziosWJ/simple-inventory/issues/43) · `ready-for-agent`

## Parent

[Phase 5 规格 #39](https://github.com/EziosWJ/simple-inventory/issues/39)

## What to build

经营者搜索客户和实物/服务，在完整销售页填写交付资料并可靠保存草稿；共享采购场景验证过的选择和保存体验，同时保留销售与直送语义。

## Acceptance criteria

- [ ] 独立新建/编辑销售页面可直接访问和刷新；从列表、详情和直送采购创建销售入口进入时保留正确关联。
- [ ] 商品和客户分页搜索采用共用能力，支持商品全字段和对象联系方式；销售只选启用客户及启用实物/服务，超过 500 条仍可查。
- [ ] 保持混合/纯服务、同商品分行报价、参考价、本地当天日期、送货默认/修改/明确空值及单位/类型确认。
- [ ] 销售创建/编辑按规格提供稳定 requestKey、结果查询、同键同内容重试及不同内容冲突；草稿、回执和审计原子持久化，旧调用兼容。
- [ ] 失败保留输入，响应丢失核实原结果，保存成功后他人再修改/过账/取消不被误认为原请求未成功。
- [ ] 沿用版本保护并提供确认后重新加载最新内容，终态只读；未保存离开提示，账号切换不复用旧请求标识。
- [ ] 保存草稿不改变库存或应收；送货单草稿及既有直送关联、取消、历史入口继续指向正确保存单据。
- [ ] 双库迁移和契约保留旧快照含空值、明细 ID、版本与流水，覆盖并发和重复保存；真实 UI 覆盖服务与直送进入完整页。
- [ ] 使用首个采购场景的简单共用组件/保存约定，不复制通用平台或重构全部业务模块；相关门禁及 Swagger 同步完成。
