# 03：采购入库草稿建档、编辑、取消与查询

**GitHub issue:** [#17](https://github.com/EziosWJ/simple-inventory/issues/17) · `ready-for-agent`

## Parent

Phase 4 规格：https://github.com/EziosWJ/simple-inventory/issues/14

## What to build

经营者为一次收货选择供应商与实物商品，分行填写成交数量和价格，保存采购草稿，编辑或取消，并按单号、供应商和日期查看；保存不影响库存或应付。

## Acceptance criteria

- [ ] 真实采购菜单、认证 API、新建/编辑/详情/分页页面交付；至少一行，系统唯一不可改单号与版本，创建记录可再次查询。
- [ ] 只选启用供应商和启用实物；类型/单位确认值保存，禁止服务采购；后端与 UI 一致，不把 mock 显隐当授权。
- [ ] 同商品可多行、不同价格，稳定明细 ID 支持后续退货；数量正且最多三位，单价非负且两位，零价允许。
- [ ] 每行数量乘单价四舍五入到分，整单累加；乘法/求和溢出拒绝，不用 float，参考价仅供带入而非成交依据。
- [ ] 草稿编辑以版本/状态条件写入，冲突保留输入；草稿取消必填原因且无库存/往来流水，终态不编辑、不删除、不重新过账。
- [ ] 业务日期、备注、创建/取消操作人时间完整；分页按单号/供应商/状态/商品/日期查询，多行商品筛选不重复计数。
- [ ] 草稿创建/编辑/取消与审计原子提交，失败不留半张单；当前库存与应付均保持不变。
- [ ] 双库覆盖同商品分行、赠品、精度/溢出、无效角色/停用/服务、版本并发、唯一单号、分页及回滚；UI 演示草稿维护。
- [ ] 沿用 JWT 和已登录账号业务范围，实际菜单按角色接入并授予 ADMIN，拒绝未登录请求；不以 mock 权限替代后端认证。
- [ ] 所需 schema/seed 使用 PostgreSQL/SQLite 逻辑版本同步的增量 Goose 迁移，不改旧版本、不用 AutoMigrate；保持现有业务数据与 API 兼容。
- [ ] 本任务业务维护与操作审计同事务，错误明确且保留表单输入；新增/修改 REST API 源注解与 Swagger 重新生成同步。
- [ ] 以公开 HTTP 和真实双库验证本任务行为，新增 contract 名含 Postgres/SQLite 并确实被门禁执行；相关后端 tests/vet、前端 lint/build 和数据库检查完成，报告失败、跳过和未执行项。
