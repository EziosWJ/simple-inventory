# Phase 4 往来页面拆分

## 页面边界

| 页面 | 用户要完成的事 | 页面内容 |
| --- | --- | --- |
| 往来余额 `/business/partner-balances` | 找到某单位在客户或供应商方向的当前欠款、待退款 | 跨单位余额列表、方向筛选、按余额符号提供收付款或退款入口、进入该方向明细；期初录入作为次要入口 |
| 往来明细 `/business/partner-ledger` | 核对一个单位一个方向的金额变化 | 必选单位与方向、实际生效期间、完整来源明细与记录详情；选定完整期间后显示期初、变动、期末，并可打印对账单 |
| 收付款 `/business/settlements` | 记录客户收款或供应商付款并纠错 | 正欠款范围内的资金表单、本类记录与详情、冲销入口 |
| 退款 `/business/refunds` | 记录向客户退款或收到供应商退款并纠错 | 待退款范围内的资金表单、本类记录与详情、冲销入口 |
| 期初录入 `/business/opening-balances` | 建账或补录启用前应收、应付并纠错 | 期初表单、本类记录与详情、冲销入口；菜单位于往来管理末尾 |

页面里的表单、记录和详情服务于同一业务任务。往来明细只负责查询和来源追溯，冲销在原业务记录详情中办理。客户和供应商方向分别展示，不抵扣；同一往来单位可以各有一行余额。

## 交互路径

1. 从余额行进入明细时带入单位和方向。直接打开明细页时先选择单位和方向；没有选单位时不加载跨单位流水。
2. 正余额提供客户收款或供应商付款入口，负余额提供对应退款入口；零余额不提供资金录入入口。菜单也能直接打开收付款和退款页并手动选择单位。
3. 退货详情提供“查看往来”和“办理退款”快捷入口。退款仍按该方向最新总余额校验，不与某张退货单逐单核销；若退货只抵了欠款，退款页明确说明当前无待退款。
4. 资金与期初确认前展示单位、方向、金额和余额变化。保存即生效；过账、取消和冲销后的余额以服务器最新结果为准。失败保留输入并说明原因。
5. 各业务页只列自己的原始记录，标明是否已冲销；冲销必填原因，原记录与反向记录均可从综合明细追溯。
6. 明细页不重复跨单位当前余额表。未选期间时查询该单位该方向全部明细；选择期间必须同时指定起止日，期初、期间变动和期末按实际生效时间计算。打印使用完整期间数据，不依赖当前分页。

## 实现与验证约束

- 保留现有余额、退款、明细和对账单 URL；新增收付款与期初 URL。更新菜单名称、排序和权限，不修改历史 seed。
- 往来记录分页接口增加服务端记录分类筛选，保证本类记录跨页完整且总数准确；同步 REST Swagger。
- 页面沿用现有蓝、灰、白配色和组件，重点用余额符号、具体动词及明确的空状态区分任务，不增加装饰性卡片。
- 更新受影响的浏览器验收脚本，执行后端检查、前端 lint/build 和数据库兼容检查。
