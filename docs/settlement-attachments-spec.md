# 往来业务附件规格

状态：Q1～Q7 与测试边界已确认；已按 to-spec 发布为 [GitHub #63](https://github.com/EziosWJ/simple-inventory/issues/63)，标记 `ready-for-agent`。后续实施以 [issue 规格](settlement-attachments-issue-spec.md)为准；本文件保留访谈后的详细设计说明。

本地实现与验证见 [交付记录](settlement-attachments-acceptance.md)。

## 业务范围

为往来管理的收付款（客户收款、供应商付款）、退款（销售退款、采购退款）、期初录入（期初应收、期初应付）增加可选附件，支持已有历史记录补传。附件归属具体往来业务记录，不归属整个往来单位；不改变金额、业务日期、往来余额或原业务生效规则。

## 文件与界面

- 支持 PNG、JPG/JPEG、PDF；同时校验扩展名与真实内容，沿用现有图片解码与像素限制。
- 每条记录最多 5 个当前有效附件，移除项不计数；单个最多 10 MB，实现统一采用 10 × 1024 × 1024 字节，并在界面说明。
- 新建表单可选择多个附件，展示文件名、大小、上传状态及可理解的错误信息。
- 列表显示当前有效附件数量；记录详情提供有效附件列表、补传、移除和附件历史。
- 图片可放大查看，PDF 可打开查看，附件可下载；预览与下载均通过鉴权访问。
- 附件历史展示文件名、上传人及时间、移除人及时间，并可查看和下载移除项的原文件。移除不可恢复为有效项，需要时重新上传。

## 保存与生命周期

- 附件全部可选；未选择附件可以直接保存业务。
- 已选择附件尚在上传或存在失败时，阻止新建业务保存。保留表单和成功项，用户可重试或主动移除失败项后再保存。
- 新建业务保存时，业务记录、附件关联和相应审计在同一数据库事务中完成；失败时不产生部分生效的往来记录。
- 网络重试沿用业务幂等机制，不能重复记账、重复绑定附件；成功上传项可在当前表单重试时复用。
- 已保存且未冲销记录允许补传、移除。补传失败不影响既有记录或附件；多个补传文件逐项展示结果，保留成功项并允许重试失败项。
- 移除只改变附件关联的有效状态，保留原文件和历史；附件操作不触发往来冲销。
- 原记录被冲销后，有效附件与历史附件全部只读；冲销记录本身不提供上传入口，查看原记录即可追溯凭证。
- 并发补传不能突破五个有效附件限制；补传、移除与冲销并发时，通过事务内状态校验确保已冲销记录不可变更附件。
- 新建时取消表单或保存失败产生的未绑定文件属于临时文件，需要有安全清理机制；不能清理已绑定文件，包括已移除附件和已冲销记录的附件。临时文件清理不得中断有效的表单重试。

## 权限与可追溯性

- 经营者共享业务附件，不按上传者隔离。有相应业务查询权限可查看、下载及查阅历史；有相应业务录入权限可补传、移除。
- 前后端均执行附件权限检查；实施时核对现有权限模型如何表达查询和录入，不把前端菜单显隐当作后端授权。
- 按文件 ID 访问、通用文件管理删除、批量删除、停用等入口均不得绕过业务附件权限和留存规则；已有绑定及历史绑定的原文件需要保护。
- 附件关联持久化具体业务记录和文件标识；上传、绑定、移除保留操作人和时间，关联变更与审计事务一致。
- 备份恢复包含附件元数据、历史关联与实际文件，恢复后有效及历史附件均可访问。

## 实施约束

- 复用现有文件存储能力，并增加明确的业务关联及留存保护；不依赖 `businessModule` 字符串代表真实业务归属。
- 保持 Handler → Service → Repository 边界，Service 不依赖 Gin/GORM；Schema 变更使用同步的 PostgreSQL/SQLite Goose migration。
- 同步 REST API 源注解，通过 `task api:docs` 生成并审查 Swagger 差异。
- 本次不扩展到库存期初、采购销售单附件、冲销附件、OCR 或银行流水识别。

## 验收要求

1. 三个入口均能无附件保存，历史记录可补传；客户与供应商方向均覆盖。
2. 合法 PNG/JPG/PDF 可上传预览下载；伪装内容、超限大小、超五个有效附件由后端拒绝。
3. 上传失败或仍在上传时不保存新业务；重试及移除失败项后可继续，不重复记账或重复绑定。
4. 补传及移除不改变往来金额；移除项普通详情隐藏、数量扣减，历史保留文件和操作信息。
5. 冲销后附件只读，原文件可访问；并发上传与冲销仍满足状态与数量限制。
6. 未登录和权限不足的用户无法上传、查看、下载或移除；通用文件入口不能绕过保护。
7. 临时文件清理与备份恢复不会丢失已绑定或历史附件。
8. SQLite 定向验证后验证 PostgreSQL；双库空库 migration 与旧数据升级均通过。新增 contract 分别使用 `TestSQLite...`、`TestPostgres...` 前缀并核对 Taskfile/CI 选择范围。
9. 定型后执行 `task db:check`、`task frontend:lint`、`task frontend:build`，报告未执行项；实际浏览器覆盖三个入口、失败重试、历史与冲销只读。
