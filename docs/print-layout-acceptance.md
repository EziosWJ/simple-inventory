# 送货单与往来对账单打印版面验收

日期：2026-10-02。任务：[送货单 #52](https://github.com/EziosWJ/simple-inventory/issues/52)、[往来对账单 #53](https://github.com/EziosWJ/simple-inventory/issues/53)。

## 已实现

- 两类单据共用居中 20pt 加粗标题、公司名称首字临时标识、公司全称及联系电话，信息区与明细表左右边界一致。
- 送货单按两列展示完整原单号、业务日期、客户名称、收货人、收货人电话和完整地址。销售录单地址改用多行输入并提示楼栋、楼层和房间号，不补造实际地址。
- 送货单末页包含合计、指定签收提示、送货人签字、收货人签字和收货日期。已过账历史资料包括空值仍沿用快照，草稿与取消单保留对应水印。
- 客户与供应商对账单复用现有完整期间及经营者资料接口；己方抬头采用本次打印时的资料。资料加载失败显示错误、禁止打印，不产生缺失己方信息的打印单。
- 对账单区分往来单位、方向、实际生效期间和期初余额，使用简洁的 ST-单位ID-C/S 标识，保留完整来源及冲销原单号。明细字号从 10px 提高到 12px，末页有金额摘要和双方确认/日期。
- 每页保留原行数上限（送货 18，对账 12），根据实际行高、头部、末页签收或确认栏及页脚空间减少行数。金额显隐与字体加载后重新测量，预览和纸面页码沿用实际分页结果。
- 同步旧验收脚本的字段标签、签收文字与动态对账页数，保留完整明细、金额及 PDF 物理页面检查。

## 验证结果

通过 `task frontend:lint`、`task frontend:build`、既有 `npm run test:delivery-note` 和新增 `npm run test:print-layout`。构建仍提示 Browserslist 数据较旧和部分 bundle 大于 500kB，不影响通过。

新增测试使用隔离的已保存单据打印投影和接口响应，运行真实打印页面、Chromium 和 Poppler；不操作业务数据库。验证居中、表格边界、完整单号单行、连续明细序号、页脚不重叠、资料失败、金额切换重分页，以及 PDF A4 物理尺寸、物理页数、全部文字边界、每页页码和仅末页出现的合计/签收或确认。

| 场景 | 真实 PDF 页数 |
| --- | ---: |
| 22 行送货，显示金额 | 2 |
| 22 行送货，隐藏金额 | 2 |
| 40 行长商品/规格/备注、长地址草稿 | 20 |
| 40 行长明细，隐藏金额 | 10 |
| 取消送货单 | 2 |
| 过账历史资料为空 | 2 |
| 无明细送货单 | 1 |
| 43 笔客户对账，含冲销原单号 | 5 |
| 43 笔供应商对账，每行双来源单号 | 7 |
| 无变动对账单 | 1 |

长内容会增加页数，完整打印，不强制裁剪到原固定页数。已目视检查两类单据的首页预览和真实 PDF 末页栅格。

## 复跑

从仓库根目录运行：

```sh
task frontend:lint
task frontend:build
cd web
npm run test:delivery-note
npm run test:print-layout
```

需要已安装的 Playwright Chromium、Python 3 和 Poppler 的 `pdftotext`。浏览器安装版本与 Playwright 默认版本不一致时，用 `PLAYWRIGHT_EXECUTABLE_PATH` 指向已有浏览器。设置 `PRINT_LAYOUT_OUTPUT_DIR` 可指定隔离证据目录，默认 `/tmp/simple-inventory-print-layout-pdfs`，包含 PDF、首页截图和结果 JSON。

本轮没有修改后端、REST API 或数据库结构；未执行 backend/db 门禁、完整 Phase 4/5 真实数据库业务验收及实体打印机测试。旧端到端脚本的标签和页数预期已同步，并做语法检查，未重跑全业务流程。
