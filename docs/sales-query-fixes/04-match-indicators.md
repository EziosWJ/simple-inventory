# 销售商品查询匹配明细与高亮统一

## Parent

https://github.com/EziosWJ/simple-inventory/issues/66

## What to build

经营者使用商品编码、名称、品牌、型号等条件查单时，能够看到真正匹配的明细，即使命中的是当前档案而不是旧单描述。

## Acceptance criteria

- [x] 由后端在销售查询响应中提供逐明细的匹配标识或匹配明细 ID 集合，前端不再独立复制关键词匹配规则。
- [x] 按单据仍返回整单，在摘要与展开明细中突出实际匹配行；按明细只返回匹配行；无商品条件时不误标所有商品。
- [x] 覆盖商品 ID、快照编码/名称/型号/规格、当前档案品牌及改名后的资料匹配；多词、大小写与字面特殊字符沿用服务端既有规则。
- [x] 匹配标识不改变单据去重、分页总数、明细合计或历史快照；不能用当前档案覆盖旧销售描述。
- [x] 扩展响应保持既有接口兼容和原权限校验；遵守 Handler → Service → Repository 边界及 PostgreSQL/SQLite 支持。
- [x] 双库 HTTP 契约和真实浏览器覆盖多商品整单、不同价格明细及当前档案/历史匹配；同步 API 源注解并生成文档。
- [x] 先定向 SQLite 再 PostgreSQL，完成数据库兼容门禁与前端 lint/build。

## Blocked by

无，可立即开始。
