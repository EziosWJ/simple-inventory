# 02：商品与服务编辑、停用和恢复

**GitHub issue:** [#3](https://github.com/EziosWJ/simple-inventory/issues/3) · `ready-for-agent`

## Parent

- Phase 2 基础资料规格：https://github.com/EziosWJ/simple-inventory/issues/1

## What to build

经营者可以编辑已保存商品与服务，包括纠正编码、类型、基本单位和参考价；可以停用、查询停用资料并重新启用，档案始终保留。本任务在已有建档查询路径上交付完整维护闭环，并独立演示编辑与状态变化。

## Acceptance criteria

- [ ] 列表与详情提供编辑入口，可维护全部已定义字段，沿用建档的必填、价格精度、空值和编码规范化规则。
- [ ] 编码可以修改，内部身份保持不变；重复编码被拒绝，其他档案与停用档案仍占用各自编码。
- [ ] 可修改实物/服务类型与基本单位，服务仍无库存行为；本阶段不虚构未实现单据的引用限制。
- [ ] 停用与恢复设置明确目标状态，重复设置同一状态后仍保持一致；新增档案默认启用。
- [ ] 停用资料可查询、查看、编辑和恢复，状态筛选和列表显示正确；不存在删除入口或接口。
- [ ] 编辑或启停成功后相关列表、详情更新；无效提交显示错误且不改变已保存资料。
- [ ] 编辑、停用与恢复各自和审计同事务提交，双库验证成功提交及审计失败整体回滚。
- [ ] 公开 HTTP 测试覆盖编码编辑冲突、类型与单位修改、价格编辑、状态幂等、停用后可查可改可恢复及未登录拒绝。
- [ ] PostgreSQL/SQLite 行为一致，任何迁移逻辑版本同步；完成页面维护演示和对应后端、前端、双库检查。
- [ ] Swagger 源注解与生成产物同步；“后续单据不选择停用资料”的规则留到单据阶段验证。
