# 销售明细表与全结果合计可读性调整

## Parent

https://github.com/EziosWJ/simple-inventory/issues/66

## What to build

经营者能优先看到销售明细和净销售金额，状态不被挤成竖排，仍能查看完整单号及全部数量分组。

## Acceptance criteria

- [x] 状态标签禁止换行且列宽足够；表格空间不足时在表格区域横向滚动，标签不溢出边框。
- [x] 净销售额列以金额为主、净数量为辅；有效退货统一以金额为主、数量为辅，表头与主要内容一致。
- [x] 无退货显示无退货或明确的零值，消除负零金额；零价实物仍显示真实零销售金额；服务退货、草稿/取消净值不适用语义保留。
- [x] 合计区使用草稿、已过账、已取消三个独立 panel；常用桌面宽度下三张等宽占满一行，窄屏按宽度换行。已过账 panel 突出净销售额，另两个 panel 展示各自原金额和状态明细，不混淆净销售额口径。
- [x] 数量合计入口放在合计标题右侧，打开 modal 查看全部商品/单位分组；modal 清楚展示销售、已退、净数量及完整单位，内容过多时在 modal 内滚动，不在合计区展开占据表格空间；窄屏使用分组卡片展示。
- [x] 合计计数明确写为若干条明细，不让用户误解成单据数。
- [x] 来源单号改为较轻的文字链接，可缩略但能够查看和复制完整单号，并保留打开原单的行为。
- [x] 客户和商品保留可读空间；常用电脑宽度下三张合计 panel 占满可用行宽、合计高度合理，明细更容易进入首屏；不改变全部筛选结果的统计口径。
- [x] 真实浏览器覆盖长客户名、长单号、多商品分组、退货/无退货、纯服务及各状态，并在桌面和窄屏复验新布局与数量 modal；完成前端 lint/build。
- [x] 若整理展示组件，只做本任务所需的局部变更；与其他任务的重叠修改通过顺序集成协调，不增加虚假的技术依赖。
