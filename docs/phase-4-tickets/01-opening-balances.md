# 01：期初应收应付录入、往来余额与冲销

**GitHub issue:** [#15](https://github.com/EziosWJ/simple-inventory/issues/15) · `ready-for-agent`

## Parent

Phase 4 规格：https://github.com/EziosWJ/simple-inventory/issues/14

## What to build

经营者按往来单位录入系统启用前的应收或应付，分次保存、查询当前余额和来源记录，录错时填写原因冲销并重录；该路径不依赖采购或销售，也不影响库存。

## Acceptance criteria

- [ ] 交付真实往来业务入口、认证 API、余额列表与期初记录详情；客户/供应商方向分开，正余额为欠款、负余额为待退款，零与尚无记录明确表达，不自动抵扣。
- [ ] 期初允许同单位多次录入正金额和必填说明，业务日期与实际生效时间分开；确认前展示余额变化，保存即生效，单号/来源、实际操作人与审计可查询。
- [ ] 人民币两位小数以准确字符串往返，拒绝零、负数、超精度及溢出；不创建历史采购/销售单或库存记录。
- [ ] 采用真实当前往来余额和不可变金额流水，原始及冲销来源可追溯，余额等于全部已提交流水累计；留出采购/销售写入同事务的必要边界，不先建通用财务平台。
- [ ] 录错不修改或删除原金额/对象；冲销必填原因、反向追加并关联原记录，同一记录最多冲销一次；形成无依据待退款时整次拒绝。
- [ ] 同单位同方向并发录入不丢更新，重复保存/冲销只生效一次；金额记录、余额及审计同事务，审计失败全回滚。
- [ ] 按单位/方向查询分页与总数一致、排序稳定；为后续交易写入复用本任务的余额与流水，不引入另一份欠款投影。
- [ ] 双库公开 HTTP 覆盖分次期初、双方向不抵扣、零/无记录、溢出、冲销限制、并发防重及审计回滚；实际页面演示录入→余额→冲销→重录。
- [ ] 沿用 JWT 和已登录账号业务范围，实际菜单按角色接入并授予 ADMIN，拒绝未登录请求；不以 mock 权限替代后端认证。
- [ ] 所需 schema/seed 使用 PostgreSQL/SQLite 逻辑版本同步的增量 Goose 迁移，不改旧版本、不用 AutoMigrate；保持现有业务数据与 API 兼容。
- [ ] 本任务业务维护与操作审计同事务，错误明确且保留表单输入；新增/修改 REST API 源注解与 Swagger 重新生成同步。
- [ ] 以公开 HTTP 和真实双库验证本任务行为，新增 contract 名含 Postgres/SQLite 并确实被门禁执行；相关后端 tests/vet、前端 lint/build 和数据库检查完成，报告失败、跳过和未执行项。
