# 04：已过账库存调整取消、反向流水与纠错路径

**GitHub issue:** [#11](https://github.com/EziosWJ/simple-inventory/issues/11) · `ready-for-agent`

## Parent

Phase 3 库存基础规格：https://github.com/EziosWJ/simple-inventory/issues/7

## What to build

经营者填写原因取消已过账调整，系统整单反向变动并保留原流水；会造成负库存时拒绝并说明另建调整的纠错路径。已停用商品的历史调整仍可按约束取消，原单及取消记录可从既有详情查询。

## Acceptance criteria

- [x] 扩展已有取消操作支持最新 POSTED，界面显示整单冲销影响并确认，取消原因非空；记录实际操作人、时间及曾经已过账的信息。
- [x] 按原明细取相反数量整单冲销，使用原商品快照，反向流水关联原单/原明细/原流水；标记取消冲销，不删除或修改原记录。
- [x] 取消冲销不重新使用原原因的增减方向校验，明确区分原始调整与取消冲销；停用商品无需重新启用即可取消历史单据。
- [x] 依据事务内当前余额校验所有反向结果非负；先加 10 后减 7 剩 3 时不能取消原加 10，且库存、原流水和 POSTED 状态全部保持。
- [x] 反向流水、库存余额、单据状态及审计同事务提交；任一项失败全单回滚，不产生部分冲销。
- [x] 重复取消、同单并发取消、过账与取消竞争不重复产生反向变动；重复已完成操作能识别结果，不兼容状态或过期内容明确拒绝。
- [x] 已取消单不可编辑、重新过账或删除；库存归零或取消原调整仍不解除商品类型与基本单位的历史锁。
- [x] 原单详情保留过账和取消的全部信息，可识别草稿取消与过账冲销；取消失败时说明原因，提示根据实物另建调整并在说明中注明原单号。
- [x] 双库公开 HTTP 行为覆盖草稿取消不变库存、混合明细整单冲销、负库存拒绝、停用商品取消、并发防重、审计失败回滚及永久商品锁；原始和反向流水累计与余额一致。
- [x] 沿用现有登录认证和已登录账号访问范围，记录实际操作人；真实菜单按现有角色菜单规则接入，不使用 mock 权限充当后端授权。
- [x] 业务修改和操作审计同事务，失败整体回滚；如新增 schema/seed，使用双库逻辑版本同步的 Goose 迁移，不改写旧版本。
- [x] 公开 HTTP 行为和真实数据库验证在 PostgreSQL/文件型 SQLite 上通过；新增 contract 确实被现有数据库门禁选中，跳过与未执行项如实报告。
- [x] API 源注解与 Swagger 重新生成，实际页面路径可演示；执行后端 tests+vet、前端 lint/build 及与改动对应的双库检查，报告结果。
