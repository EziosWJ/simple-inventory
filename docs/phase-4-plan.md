# Phase 4 采购与销售需求讨论记录

状态：已确认。Q1～Q41 已逐轮确认，Q42 已确认整体范围、边界与验收方案，需求访谈完成。

## 已确认

- Q1：采购入库与销售出库在同一阶段规划，按采购 → 销售顺序分批实现，共同确认单据、金额及库存规则。
- Q2：采用一张采购入库单记录一次收货、一张销售出库单记录一次交付的首版方向；直送处理见 Q4/Q23/Q36/Q39。
- Q3：先记录成交金额；相关范围已在 Q5～Q7 进一步确认。
- Q4：供应商直送客户仍记录关联采购入库和销售出库，唯一逻辑仓库不代表货物必须经过店面；具体流程见 Q23/Q29/Q36/Q39。
- Q5：赊账是日常情况，本阶段纳入简单应收、应付及分次收付款；财务总账留到后续，结算与纠错见 Q9/Q12/Q18/Q24。
- Q6：本阶段记录实际采购与销售金额，暂缓库存成本和毛利核算。
- Q7：本阶段不记录逐台 SN；送货后需要客户签收纸质单据，将基础送货单打印提前纳入本阶段。
- Q8：人民币单价保留两位小数，数量最多三位；每行金额四舍五入到分，整单金额为行金额之和。填写最终成交单价，本阶段暂不单独计算折扣、运费和税额。
- Q9：客户收款只减少该客户的总欠款，不分配到具体销售单；系统不据此推断某张销售单已结清。供应商采用对称规则（Q12），不支持普通预收预付（Q13），取舍见 ADR-0013。
- Q10：送货单提供显示金额/隐藏金额两种打印方式，包含经营者名称、客户、送货地址、单号、日期、商品规格、单位、数量、备注与签收栏。允许已保存草稿提前打印并标明“未过账”；正式单据按已过账内容打印。
- Q11：销售单允许实物与服务混合，也允许纯服务；服务计入成交金额及应收，不产生库存变动。采购入库单本阶段只接受实物商品。
- Q12：供应商付款同样只减少供应商总欠款，不分配到具体采购单。同一往来单位的应收、应付分别保留，不自动抵扣。
- Q13：本阶段不记录超额普通收付款、预收或预付；普通收付款限定在对应当前欠款范围内。退货/交易取消产生的待退款及实际退款按 Q16/Q18/Q27 处理。
- Q14：支持录入系统启用前的期初应收、期初应付，填写说明并保留审计，不补造历史交易单、不影响库存；录入及纠错按 Q25 执行。
- Q15：日常存在退货，本阶段支持销售/采购的真实实物退货；分次部分退货、原单关联、计价和退款见 Q17/Q18/Q21/Q26/Q34/Q35。
- Q16：支持销售退货后向客户退款、采购退货后收到供应商退款；退款不超过当前待退款余额（Q18），纠错见 Q24/Q35。
- Q17：退货关联原已过账单据，允许分次、部分退货，累计不得超过原数量；按原成交价计算退货金额。采购退货同样处理，并拒绝导致负库存的退货；金额尾差和取消见 Q21/Q26。
- Q18：退货先抵减同一客户的总欠款，超出部分形成待退款；实际退款不得超过当前待退款金额。供应商侧采用相同规则，应收与应付分别计算，不跨方向抵扣。
- Q19：业务单据草稿可编辑、过账后锁定、取消追加反向记录；原采购/销售单存在生效退货时先处理退货。取消同时反向处理库存与往来金额，库存不足整单拒绝。真实退货使用退货单，收付款录错冲销后重录，原记录保留。具体约束见 Q24/Q25/Q27/Q35。
- Q20：允许填写业务日期，用于单据展示和查询；库存仍按系统实际过账时间生效，保留实际操作时间，不倒签或重算历史库存。收付款分别记录实际收付日期和系统录入时间。
- Q21：本次部分退货金额等于“累计生效退货数量乘原单价并四舍五入到分的金额”减去“此前已生效退货金额”。全部退完时累计金额等于原行金额；允许极小数量的一次退货金额为零，但保留数量。取消按 Q26 逆序处理。
- Q22：本阶段不支持服务退费；销售退货只针对实物明细，不加入服务按金额退费功能。录错服务销售仍按单据纠错规则处理，不将整单纠错取消解释为部分服务退费。
- Q23：直送使用两张关联单据，先过账采购入库，再过账销售出库，分别核对采购价与销售价；界面展示关联单据及状态。本阶段不提供同时过账两张单据的一键操作，允许两次操作之间库存暂时增加。
- Q24：普通收款、付款与退货退款确认保存即生效，提交前展示往来单位、金额及余额变化；保存后不能编辑金额或对象，录错冲销后重录，原记录保留。冲销不得形成无业务依据的预收预付，交易取消及退货取消场景见 Q27/Q35。
- Q25：期初应收/应付可分多次录入，每次为正金额并填写说明，区分应收、应付；确认保存即生效。录错保留原记录，冲销后重录，不覆盖当前余额；冲销会形成无依据待退款时拒绝。
- Q26：只能取消原明细上最近一次仍生效的退货；取消较早记录前须逆序取消后续退货。取消恢复数量额度并反向记回该退货的原金额，不重算其他历史记录。多明细退货单须每行都满足条件才能整单取消。
- Q27：取消录错的已过账采购/销售单时，原收付款保留，库存与交易金额反向处理；因此产生的负往来余额形成待退款，可以实际退款或被后续正确单据抵减。仍须无生效退货且不产生负库存。与 Q25 期初欠款冲销不得形成无依据待退款的规则区分。
- Q28：销售单过账时保存客户名称、商品资料、送货联系人/电话/地址及经营者抬头/联系方式快照，旧送货单重印沿用原快照；新销售单默认带入客户档案，允许修改本次送货资料，草稿打印反映当前已保存内容。
- Q29：首版直送一张采购单关联一张销售单，实物商品和数量一致，采购/销售价格可以不同，销售单可另加服务费。普通备货采购与后续销售无需逐单关联。
- Q30：采购/销售明细允许零单价，数量必须为正；零价实物正常出入库，零价服务不影响库存。禁止负单价，退货使用专门单据。
- Q31：收付款与退款记录收付方式，包括现金、微信、支付宝、银行转账、其他；交易流水号和备注选填。本阶段不管理银行账户余额、不上传凭证附件。
- Q32：提供往来余额列表，以及按单位、日期查询的明细账，客户/供应商方向分别展示；明细包括期初欠款、采购/销售、退货、收付款、退款与冲销，显示变动后余额并可追溯来源单据。支持打印选定期间对账单，展示期初余额、期间变动与期末余额；本阶段不提供 Excel 导出。
- Q33：沿用现有已登录账号访问范围，可操作本阶段业务，记录实际操作人；菜单按现有角色配置显示，不增加按单据所有人或岗位划分的授权规则。
- Q34：一张退货单只对应一张原已过账采购/销售单，可包含原单多条实物明细；不同原单的退货分别记录。
- Q35：取消退货保留实际退款记录，库存反向处理并重新计算往来余额；若形成新欠款，界面明确提示。退款本身录错须另外冲销退款。采购侧同样处理，库存不足拒绝整单取消。
- Q36：直送销售过账前确认关联采购已过账且实物商品与数量一致；每张直送采购最多关联一张未取消销售单，已取消关联历史仍保留。取消关联采购前先取消关联销售；直送两单的草稿修改不得绕过过账时的一致性核对。
- Q37：首版送货单和对账单采用 A4 纵向，长单自动分页，显示单号/页码，合计位于末页；送货单保留纸质签收栏。经营者名称、电话、地址统一维护，新单带入，已过账送货单保持原快照。本阶段不增加电子签名或签收照片上传。
- Q38：往来明细账与对账余额按系统实际生效时间计算，并展示业务日期；补录、取消及冲销计入实际操作期间，不将变动倒签到以前期间或重写旧记录。期间期初/期末余额从当时已生效的金额流水计算，不用当前余额代替。
- Q39：直送客户直接向供应商退货时，仍先记录关联原销售单的销售退货，再记录关联原采购单的采购退货；分别核对数量、金额并整单过账，库存先增后减，允许两次操作之间暂时有库存。
- Q40：停用商品/往来单位禁止在新采购/销售中选用，已有草稿过账重新校验并拒绝；采购须供应商身份、销售须客户身份。历史退货、收付款、退款与冲销可继续处理，无需重新启用资料；库存、原单及余额约束继续适用。
- Q41：采购/销售单允许同一商品分行并各自定价；库存按商品汇总校验和变动，退货按原明细控制数量及价格。直送两单按实物商品汇总数量核对，不要求行数或采购/销售单价一致。
- Q42：用户已确认本阶段完整交付范围、范围外事项和验收方案，双方已达成共同理解，需求访谈完成。

## 整体核对（Q42 已确认）

### 本阶段交付

1. 采购入库、销售出库：一次收货/交付一张单，草稿、整单过账、取消，单号及历史记录保留。服务可与实物混合销售或单独销售；采购仅实物。同商品可分行定价，数量必须为正、单价可为零。
2. 直送：关联采购/销售单，按实物商品汇总数量一致，先采购后销售，分别过账。取消先处理关联销售；直送退货先销售退货后采购退货。
3. 采购/销售退货：一张退货单对应一张原已过账单，支持分次部分实物退货，原明细累计数量不超过原数量，金额按原成交价累计取整；只能逆序取消仍生效的退货，不改写后续历史金额。
4. 往来余额：客户与供应商方向分别计算，不自动抵扣；支持期初应收/应付、收付款、退货退款和保留原记录的冲销，按往来总余额结算，不逐单核销。
5. 收付款和期初欠款确认保存即生效，录错冲销后重录；普通收付款不得超过当前欠款，退款不得超过当前待退款。退货或原交易取消可形成待退款，后续正确交易可抵减；期初冲销不得制造无依据待退款。
6. 当前库存、库存流水及来源追溯接入采购、销售、退货和取消冲销；往来余额列表、明细账及来源追溯接入所有金额变动。
7. 送货单与期间对账单 A4 打印：送货单金额可显隐、纸质签收，草稿打印标记未过账；已过账送货资料保留快照。对账按实际生效时间计算期初/期间/期末余额，同时展示业务日期。
8. 沿用已登录账号访问范围和真实菜单规则，保留实际操作人及事务审计，保持 PostgreSQL/SQLite 行为一致。

### 本阶段范围外

- 库存成本与毛利、SN、服务退费、财务总账、银行账户余额。
- 普通预收预付/超额收付款、跨客户供应商方向自动抵扣、逐单核销。
- 折扣/运费/税额单独计算、Excel 导出、凭证附件、电子签名和签收照片上传。
- 多仓、负库存、历史库存倒签或重算、同时过账直送两单的一键操作。

### 实现时沿用的约束与验收方案

- Phase 3 的空型号/规格快照缺口先收尾，再接入新业务；旧 issue #7、#10、#13 关闭条件不因本次规划改变。
- Handler → Service → Repository、Goose 双库同步迁移、固定精度数量/金额、真实认证菜单、Swagger 源注解与生成产物同步。
- 库存余额、库存流水、往来金额变动、单据状态和操作审计原子提交；失败整单回滚，同单重试/并发只生效一次，收付款及退款并发不能突破余额上限，退货并发不能突破原明细额度。
- 公开 HTTP + PostgreSQL/文件型 SQLite contract 覆盖草稿无业务影响、同商品分行汇总、非负库存、历史空值快照、退货金额尾差/逆序取消、总余额结算、退款/冲销、停用历史处理及来源追溯，核对所有新增测试实际被门禁选中。
- 真实浏览器验收采购 → 销售 → 收付款 → 部分退货 → 退款 → 冲销、直送及退货、期初欠款、送货单/对账单金额显隐与多页打印。
- 实现完成执行 `task check`、`task db:check`，报告通过/失败/跳过/未执行项。

Q42 已确认以上范围、边界与验收方案。正式规格已发布为 [GitHub #14](https://github.com/EziosWJ/simple-inventory/issues/14)，本地见 [Phase 4 规格](phase-4-spec.md)；纵向任务发布记录见 [任务索引](phase-4-tickets/README.md)。

## 现有事实与约束

- 商品与服务、统一往来单位和唯一逻辑仓库已实现。
- 库存调整、余额与流水能力已实现。最近一次验收发现已过账单据的空型号/规格快照会回退到当前商品档案；#7、#10、#13 保持开放，该缺口需在新业务接入前收尾。
- 沿用库存非负、固定精度数量/金额、事务审计和双数据库支持约束。
