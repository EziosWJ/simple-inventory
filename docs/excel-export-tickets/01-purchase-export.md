# T01: 采购入库明细导出（含三页共用导出工具）

Issue：[#86](https://github.com/EziosWJ/simple-inventory/issues/86)

**What to build:** 在采购入库页，按当前查询框的条件下载「采购明细」Excel 文件。这是打通全链路的 tracer bullet：它同时建立三页共用的两件工具（后端 xlsx 写入包、前端下载流程），销售出库与往来明细两个页面随后直接复用。

**Blocked by:** None（可立即开始）。

**Status:** 已实现并验收（2026-10-12）

- [x] 采购入库页两个视图下都能点「导出明细 Excel」，导出的都是明细，与当前视图无关
- [x] 导出内容与页面「按明细」视图在同一查询条件下的结果一致（筛选、排序、退货与净额口径）
- [x] 明细 sheet 共 17 列、首行为表头、末行为行数与原金额合计；合计 sheet 的金额三状态与数量分组与页面合计口径一致
- [x] 数量与金额是数值单元格、日期与时点是文本、不适用的单元格为空
- [x] 文件名为 `采购明细_20260801-20261012.xlsx`；无日期条件时为 `采购明细_全部_20261012.xlsx`
- [x] 空结果仍产出含表头的合法文件
- [x] 匹配行数超过 10000 时先弹确认，超过 100000 时后端拒绝并给出中文提示
- [x] 导出失败时页面显示中文原因，按钮在导出中处于禁用状态
- [x] 导出不改变任何采购、库存或往来数据
- [x] 双库契约测试各一份（`TestSQLite` 与 `TestPostgres` 前缀，确认被 Taskfile 与 CI 各选中一次），通过 HTTP 取回 xlsx 后用 excelize 读回断言表头、单元格值、行数与合计
- [x] `task backend:check`、`task api:docs`（核对生成差异）、`task frontend:lint`、`task frontend:build` 通过

## 边界

- 后端硬上限 100000 行；导出不写操作日志；导出端点不加后端权限校验，与同类查询端点保持一致。
- 不复用列表端点加格式参数；不建通用导出框架或配置化导出。
- 导出内容固定为明细，不导出「按单据」视图的单据行。

本任务会改动前端业务接口文件与后端接口文档生成物，与 T02、T03 存在同文件冲突，集成时按顺序合并。
