# 销售查询状态隔离与请求依赖整理

## Parent

https://github.com/EziosWJ/simple-inventory/issues/66

## What to build

修复未提交筛选输入被翻页、排序、详情操作覆盖的问题，消除打开和关闭详情引起的列表及汇总重复请求，让查询和原单查看可以连续可靠地使用。

## Acceptance criteria

- [x] 先做局部整理：将销售详情、单据视图和明细视图的展示按职责分离，保持现有页面骨架及业务语义，不建立通用 CRUD 框架。
- [x] 区分筛选输入、已应用条件、视图分页排序和详情来源状态；只在已应用筛选条件发生变化或明确重置时同步输入。
- [x] 填写日期或关键词但未查询，随后翻页、排序、切换视图、打开和关闭详情，输入不被非筛选 URL 参数变化覆盖。
- [x] 客户或商品选择后立即填写日期并查询，实际请求和界面保留这些日期，不依赖等待上次请求完成。
- [x] 打开及关闭详情不触发列表和全结果合计重查；详情请求只随销售 ID 变化或明确刷新发生。
- [x] 浏览器前进后退、详情/编辑返回仍恢复已应用条件、视图、排序、每页条数及对应页码。
- [x] 查询函数、URL 参数处理和业务动作展开为可读代码，避免将状态与请求流程挤在长行中。
- [x] 沿用真实浏览器入口验证行为与请求次数，并通过前端 lint/build；若修改共用查询钩子，回归采购等调用方，保持其已约定行为。
