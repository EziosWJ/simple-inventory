# 独立直送详情与确认

独立直送详情继续使用页面载体：先展示供应商、客户、业务日期、状态与采购／销售双金额，再展示实物和服务的实际明细。送货资料及操作记录默认折叠；有生效退货时禁止整笔取消的提示和退货入口保持可见。原采购、原销售与送货单打印链接仍从详情操作区进入。

确认直送使用单据布局的宽屏弹窗，短屏正文独立滚动，操作按钮保持可达。确认主体列出业务对象、日期、采购和销售金额、每行双侧单价／金额、服务行无采购影响、客户已实际收货依据、两侧往来方向，以及实物采购增加与销售减少的成对流水和库存净零说明。确认动作沿用直送原有同事务入口；取消确认不写入，未知结果仍通过原单 ID 与版本核实，不建立新的恢复流程。整笔取消保留原短确认与原因输入。

直送退货追溯把关联单据完整表格放在折叠区；过账前必需的先销售退货后采购退货提示、导航按钮及风险说明留在折叠区外，避免必要顺序被隐藏。

定向回归由 `web/tests/document-direct-modals.mjs` 在隔离 mock API 与 Vite 端口 4215 执行，覆盖确认取消零写、重复提交保护、同单未知结果核验、版本变化停止旧版本重试、服务行采购影响、退货取消限制与追溯顺序。截图位于 `/tmp/issue90-direct-detail.png`、`/tmp/issue90-direct-confirm.png`、`/tmp/issue90-direct-confirm-narrow.png` 和 `/tmp/issue90-direct-trace-risk.png`。
