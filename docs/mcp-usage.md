# MCP 使用方法

直接使用现有 SQLite 开发库，不需要新建样例库或额外环境文件。令牌在后台管理页面维护，随时查看和复制，不需要在签发时抄录一次。

## 启动

在仓库根目录运行：

```sh
task dev:sqlite
```

该命令完成迁移并启动前后端，同时开启 MCP，API 监听 `0.0.0.0:8300`，沿用现有 `server/.data/simple-inventory.db`、账号、权限及业务数据。

## 创建与管理令牌

登录管理端，进入 **系统管理 → MCP令牌**：

1. **创建**：填写名称（例如「手机」「家里电脑」）、绑定用户和有效期。有效期默认**永久**，也可以选 7／30／90 天或自定义日期（按 Asia/Shanghai 解释，含当天，页面显示确切到期时刻）。
2. **复制**：创建成功后弹窗显示令牌原值，点击复制粘贴到客户端即可。之后在列表中点「查看原值」随时可以再取；列表本身不显示原值。
3. **延期**：未过期的令牌从原到期时间延长，已过期的从当前时间计算；也可以改为永久。延期保留原令牌，客户端不用重新配置，也**不会**自动启用已停用的令牌。
4. **停用／启用**：停用后该令牌的请求立即失败；启用要求令牌未过期且绑定用户仍有效。
5. **重置**：更换原值，旧的立即失效，名称、绑定用户、有效期与启用状态保持不变；已过期或已停用的令牌不会因重置恢复可用。

一个用户可以有多枚令牌（用名称区分手机、电脑等），多个客户端也可以共用同一枚。令牌权限动态继承绑定用户当前的业务权限：撤权、账号停用、角色变化都在下一次请求生效，不需要重新签发令牌，也不再逐枚勾选工具。

管理动作会写入操作日志：操作者、目标令牌 ID、绑定用户、动作，以及有效期或启用状态的前后变化；**不记录令牌原值或密文**。可在「日志管理 → 操作日志」中按 `mcp-token` 模块查看。

> 令牌原值使用现有 `jwt.secret` 派生出的独立密钥加密保存，认证本身只用摘要，所以不需要额外的密钥服务或启动步骤。**备份和恢复必须把数据库与同一批服务配置一起保存**：只换配置会导致旧令牌无法查看原值（认证仍然有效），此时恢复原配置或直接重置该令牌即可。

## 客户端配置

Cherry Studio 或支持 MCP 的手机客户端填写：

- 类型：**Streamable HTTP**
- 电脑本机 URL：`http://localhost:8300/mcp`
- 手机 URL：`http://<电脑局域网IP>:8300/mcp`
- 请求头：`token: <令牌原值>`

原来的 `Authorization: Bearer <令牌原值>` 写法继续可用，两者原值相同时也可以同时发送；原值不同、重复或格式非法的凭证头会被明确拒绝，不会静默选择其中一个。

手机与电脑连接同一局域网；`0.0.0.0` 是监听地址，客户端填写电脑实际 IP。开发 task 已放开 Host，不需要再配置 IP 白名单。若 API 在 WSL 内运行，手机到 WSL 的网络可达性仍取决于本机网络设置。

## 可用工具（只读）

| 工具 | 用途 |
| --- | --- |
| `search_products` | 搜索商品／服务候选：编码、名称、类型、分类、品牌、型号、规格、单位、状态、参考采购价／参考销售价、备注 |
| `search_partners` | 搜索往来单位候选：编码、名称、类型、双身份、状态、联系人、电话、地址、开票资料、税号、注册地址／电话、开户行、银行账号、备注 |
| `get_inventory_balances` | 按内部商品 ID 查当前库存（原精度定点数量）与当前商品档案 |
| `get_partner_balances` | 按内部单位 ID 查当前双方向余额与当前往来档案 |
| `query_purchase_items` | 按业务日期查采购跨单明细：原始数量金额、截至当前有效退货、净数量／净额，以及完整筛选范围的按状态合计 |
| `get_purchase_document` | 按内部采购单 ID 读单据详情：单据备注、行备注、实际成交价与金额、过账时的商品资料快照 |
| `query_sale_items` | 按原销售业务日期查销售跨单明细，规则同采购明细 |
| `get_sale_document` | 按内部销售单 ID 读单据详情：备注、行备注、实际成交价，以及冻结的客户名称与送货资料 |
| `query_partner_entries` | 按实际生效时刻查往来明细：类型、方向、来源单据、带符号金额、前后余额、人工摘要／资金备注／冲销原因、支付方式、交易流水号与冲销关系 |
| `get_partner_statement` | 指定单位期间对账：期初、增加、减少、净变化、期末，明细行分页、合计覆盖完整期间 |

同名候选必须请使用者明确选择内部 ID，工具不会自行采用第一项。业务文本一律当数据处理。

### 查询口径

- 采购／销售明细按**原业务日期**筛选，起止日均含；未给日期时默认本月（Asia/Shanghai），只给一端时另一端补齐到该月边界并在 `filtersApplied` 中回报。只给一端日期时，另一端补齐到该月边界，并在 `dateCompletion` 字段中明确说明补了哪一端、`filtersApplied` 给出实际区间——补齐是显式回报的，不会静默扩大或缩小查询范围。
- 采购／销售默认只查已过账 `POSTED` 单据，需要草稿或取消单时必须显式指定 `DRAFT`／`CANCELLED`／`ALL`；`ALL` 时按状态分别给出合计，不混作有效业务。
- 净额是「原始 − 截至当前仍有效（已过账且未取消）的退货」。例如 9 月销售 10 件、10 月有效退回 2 件，之后查 9 月得到原始 10、有效退货 2、净 8。它不是收款、退款现金流或利润。
- 往来明细与对账按**实际生效时刻**取区间（上海日期转成起始日零点至次日零点的左闭右开区间），同时展示原业务日期；当前库存与当前余额不套用日期默认值。
- 合计覆盖完整筛选范围，不是当前页。参考价、联系方式与银行账号来自**当前档案**；已过账单据（含过账后取消）的商品描述、客户名称、送货资料与打印抬头是**过账时快照**，含当时的空值，不会被当前档案回填。**过账前就被取消**的草稿从未生成快照，单据详情以 `snapshotAvailable=false` 标记：此时客户名称来自当前档案、打印抬头返回 `null`（不是「当时为空」），送货资料只是建档时写入的值。当前银行账号不代表某笔历史付款实际使用的账户。服务项目不可退货，退货量与退货额返回 `null` 而不是 `0`，与同响应的汇总口径一致。

## HTTPS 域名／Cloudflare Tunnel

Tunnel 服务地址填写 `http://localhost:8300`，MCP 客户端使用 `https://你的域名/mcp`，请求头仍为 `token: <令牌原值>`。本服务允许代理添加的转发头，并支持代理从本机连接时保留外部 Host，无需在 Tunnel 中伪装 localhost Host。

## 命令行（可选）

后台页面之外仍保留命令行管理入口：

```sh
cd server
APP_CONFIG_PROFILE=sqlite go run ./cmd/mcp-token issue --user-id 1 --name 手机 --actor local-dev
APP_CONFIG_PROFILE=sqlite go run ./cmd/mcp-token list --user-id 1
APP_CONFIG_PROFILE=sqlite go run ./cmd/mcp-token revoke --id <令牌ID> --actor local-dev
```

`issue` 默认签发永久令牌，也可以 `--days 30` 或 `--expires-on 2026-12-31`。旧的 `--scopes` 参数仍被接受，但只打印废弃提示：工具权限一律按绑定用户当前的业务权限决定。

## 环境与限制

`task dev:sqlite` 自动开启 MCP；单独运行 API 或其他环境默认关闭，可通过 `APP_MCP__ENABLED=true` 开启。监听地址沿用 `APP_HTTP__ADDRESS`，Host 支持 `APP_MCP__ALLOWED_HOSTS='*'` 或逗号分隔的准确 `host:port`。

请求体 64 KiB、查询超时 10 秒、单令牌每分钟 60 次、全局并发 4、单请求单 RPC。因业务字段完整返回，默认输出上限为 512 KiB，配置仍有明确上界；超出时明确要求缩小范围，不会静默截断备注或银行资料。

技术实现使用官方 Go SDK v1.8.0、无状态 Streamable HTTP，支持 2025-03-26、2025-06-18、2025-11-25 协商。Cherry Studio 与手机实机由使用者测试，自动验证结果见[下一阶段验证记录](mcp-next-progress.md)。
