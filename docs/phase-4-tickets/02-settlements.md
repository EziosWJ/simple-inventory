# 02：按往来总欠款记录收付款、分次结清与冲销

**GitHub issue:** [#16](https://github.com/EziosWJ/simple-inventory/issues/16) · `ready-for-agent`

## Parent

Phase 4 规格：https://github.com/EziosWJ/simple-inventory/issues/14

## What to build

经营者对已有欠款记录一次或多次实际收款/付款，查看余额变化、收付方式和来源；录错保留原资金记录，冲销后重录，不分配到具体采购/销售单。

## Acceptance criteria

- [ ] 交付收款/付款真实表单、记录列表/详情与认证 API；按往来单位客户/供应商总余额结算，不展示推断的单据未结/结清状态。
- [ ] 确认前展示对象、方向、正金额和前后余额；保存即生效，之后不编辑金额/对象、不删除；业务日期及实际生效/操作人完整记录。
- [ ] 普通收款/付款仅允许当前对应方向余额为正且金额不超过欠款；零、负金额、超精度、溢出及自由预收预付拒绝；支持分次结清。
- [ ] 记录现金/微信/支付宝/银行转账/其他，交易流水号和备注选填；不建银行余额或上传凭证。
- [ ] 冲销必填原因，保留原记录并追加反向流水，同记录最多冲销一次，原始/冲销均可查看；重复提交和响应丢失重试不重复记账。
- [ ] 事务内余额约束阻止并发超额收付款，不使用进程单锁替代数据库一致性；余额、流水、资金记录与审计原子提交。
- [ ] 已有余额的停用或已改角色往来单位仍可历史结算；不靠角色改动清除旧欠款。
- [ ] 双库覆盖分次/超额/并发、双重身份、停用历史、实际操作人、重复冲销和审计失败回滚；可基于期初欠款独立演示。
- [ ] 沿用 JWT 和已登录账号业务范围，实际菜单按角色接入并授予 ADMIN，拒绝未登录请求；不以 mock 权限替代后端认证。
- [ ] 所需 schema/seed 使用 PostgreSQL/SQLite 逻辑版本同步的增量 Goose 迁移，不改旧版本、不用 AutoMigrate；保持现有业务数据与 API 兼容。
- [ ] 本任务业务维护与操作审计同事务，错误明确且保留表单输入；新增/修改 REST API 源注解与 Swagger 重新生成同步。
- [ ] 以公开 HTTP 和真实双库验证本任务行为，新增 contract 名含 Postgres/SQLite 并确实被门禁执行；相关后端 tests/vet、前端 lint/build 和数据库检查完成，报告失败、跳过和未执行项。
