# 03：采购保存并过账与操作结果核实

**GitHub issue:** [#42](https://github.com/EziosWJ/simple-inventory/issues/42) · `ready-for-agent`

## Parent

[Phase 5 规格 #39](https://github.com/EziosWJ/simple-inventory/issues/39)

## What to build

经营者核对整张采购单后直接保存并过账；保存失败不入账，过账失败留下同一草稿，响应丢失时展示实际状态并安全重试。

## Acceptance criteria

- [ ] 完整页提供明确的保存草稿和保存并过账操作；提交前确认对象、日期、明细、合计及库存/应付影响，取消确认不提交。
- [ ] 确认后安全保存，再以返回的同一单据 ID 和版本过账；保存失败不继续过账，不额外生成另一张草稿。
- [ ] 过账失败保留已保存草稿、单号、输入及清晰原因，能继续编辑或对同一单据重试；不回滚删除已保存草稿。
- [ ] 过账响应丢失或冲突先查询真实状态；核实中不误报成功/失败、不盲目重放，已过账/取消/版本变化各有正确操作。
- [ ] 另一个经营者修改或取消后停止旧确认，不自动过账新版本；重复过账保持一次库存、应付、状态和成功审计效果。
- [ ] 保留分行汇总、零价/零金额、停用复核及直送先采购后销售的规则，实际生效时间仍在锁后取得。
- [ ] 公开双库契约及真实浏览器覆盖保存失败、库存/资料失败、提交后丢响应、并发、重复点击和他人改变状态。
- [ ] 相关门禁和 API 文档同步完成，记录通过/失败/跳过/未执行项。
