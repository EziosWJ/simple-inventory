## 修复结果

- 四个购销、退货列表状态筛选复用公共 Select，默认高 36px、填满所在列。
- 搜索触发按钮空值和单行高 36px，随长描述换行自动增高；尺寸使用现有控件高度 token。
- 共享搜索选择器启用紧凑分页，统计和翻页分行。在 240px/270px 容器以及 1024px/1440px 窗口不溢出。大表格分页默认布局保留。
- 购销新建、编辑及其他五个整页表单使用居中离开确认。继续操作保留输入，确认离开保留来源查询参数。修改还原、首次进入和保存成功后的空表单不误报修改；保存失败不重置基线。
- 五类业务新建、编辑弹窗的取消、X、Escape、遮罩均通过未保存保护。确认框打开后，底层编辑框暂停键盘和遮罩关闭；放弃后关闭，继续编辑保留原值。
- 保存期间禁止表单编辑与直接放弃，避免新输入被成功响应清掉；刷新/关闭标签页继续使用浏览器原生 beforeunload 提醒。购销保存和过账结果待核实的保护语义保留。
- 默认焦点落在继续编辑按钮。遮罩 mousedown 默认失焦会晚于 React 更新，因此聚焦延后到下一帧。过账预览或资金提交确认已打开时，离开决策仍居最上层，底层确认暂停键盘事件。

本轮仅修改前端、回归脚本和文档。脚手架管理及示例页面未接入业务离开保护；公共确认框的新行为由可选参数启用。

## 回归入口

```sh
task frontend:lint
task frontend:build
cd web
npm run test:business-ui
```

浏览器脚本需要已安装的 Playwright Chromium，也支持通过 `PLAYWRIGHT_EXECUTABLE_PATH` 指定现有 Chromium。本机使用 `/home/wangjian/.cache/ms-playwright/chromium-1246/chrome-linux64/chrome`。

`tests/business-ui.mjs` 自行启动 4199 端口 Vite，所有 API 响应使用隔离夹具：23 个路由状态 × 两种桌面窗口、32 个搜索选择器实例、240px/270px 下零结果/失败重试/多页结果、购销双返回入口及过账预览时浏览器后退、五个整页表单、十个新建/编辑弹窗状态及保存边界。断言确认框位于视口在按钮点击之前执行，避免 Playwright 自动滚动掩盖原问题。

真实业务回归使用单独的新 SQLite 数据库 `/tmp/simple-inventory-ui-fixes-acceptance.db` 与 API `127.0.0.1:18119`，未连接现有业务库：

```sh

PHASE5_API_URL=http://127.0.0.1:18119 node tests/phase5-sale-drafts.mjs
PHASE5_API_URL=http://127.0.0.1:18119 node tests/phase5-purchase-post.mjs
PHASE5_API_URL=http://127.0.0.1:18119 node tests/phase5-sale-post.mjs
```

四项均通过，覆盖真实草稿保存、重复商品、金额、刷新离开警告、响应丢失恢复、双账号版本冲突、同单据重试、过账失败和库存不足。草稿脚本补充了确认框视口及默认焦点断言。
