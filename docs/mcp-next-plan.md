# MCP 后续需求讨论

状态：Q1～Q14 产品决定已确认，需求访谈收敛；完整规格见 [MCP 后续实施规格](mcp-next-spec.md)。已按该规格实施并通过验证，结果见[实施进度与验证记录](mcp-next-progress.md)。

## 已有基础与用户意图

- 用户已实测确认现有四工具可用，HTTP 与 Cloudflare Tunnel 均能访问。
- 后台提供令牌配置，保存后持续生效，支持点击查看与复制。
- 新客户端使用 `token: <令牌原值>`，同时兼容既有Bearer写法。
- 扩充采购／销售和往来明细／对账只读查询，范围与时间口径已确认。
- 沿用正常开发入口和现有业务库，不恢复额外样例环境。

## 现状事实

- 凭证目前已经持久化到数据库，不因 API 重启丢失；默认有效30天。
- 数据库目前仅保存摘要，因此后台无法还原旧令牌明文；支持后续查看／复制需要调整保存方式，不能凭摘要还原。
- 凭证绑定系统用户，工具权限为 scope 与用户当前业务权限的交集。停用账号、撤权和吊销后下次请求生效。
- 目前仅CLI管理凭证，没有后台令牌管理页；当前接收 `Authorization: Bearer <token>`。
- 首批四工具为商品搜索、往来搜索、指定商品当前库存、指定单位双方向当前余额。
- 已核对可复用查询：采购／销售 `Page`、`Detail`、`ItemPage`；库存 `EntryPage`；往来 `FilterPage`、`Statement`、`Overview`。采购／销售明细已有全匹配集汇总，不需要拿当前页推算总数。
- 采购／销售按业务日期查询；往来与库存流水还涉及实际生效时刻。净销售额不是利润，往来余额不是某张单据未结金额。
- 往来对账单当前无分页，往来明细存在读取后内存分页的实现，扩展MCP时需有界查询窗口。
- Web已有系统管理、用户及角色授权页面；通用配置管理不是现成的MCP令牌管理模块。

## 第一轮已确认

- Q1：有效期可以选择，默认永久有效；支持延期、停用和重置，重置后原令牌立即失效。延期起算与停用状态保持见第二轮。
- Q2：先由管理员统一管理，令牌绑定已有系统用户，支持创建、查看、复制、停用和重置；继续遵循绑定用户的当前业务权限。
- Q3：新客户端采用 `token: <令牌原值>`，不需要Bearer前缀；兼容已有 `Authorization: Bearer <token>` 客户端。
- Q4：本轮优先扩充采购／销售查询（A）与往来明细／对账（B）。库存变动追溯、经营统计／排名不纳入本轮。
- 上述是产品决定，尚未修改实现或将讨论文件当作最终实施规格。

## 第二轮已确认

- Q5：延期保留原令牌，客户端不必重新配置；未过期从原到期时间延长，已过期从当前时间重新计算并恢复有效期；已停用的令牌不会因延期自动启用。
- Q6：旧摘要令牌继续可用，后台标记“旧版令牌，重置后可查看”；重置生成支持查看／复制的新令牌，原值立即失效。
- Q7：不再要求逐令牌勾选工具；令牌继承绑定用户可用的MCP只读查询权限，新增工具随对应业务权限自动可用，不必重签令牌。撤权仍在下次请求生效。旧令牌也统一继承当前业务权限，不要求重新签发。
- Q8：采购／销售支持按客户、供应商、商品、单号查询，也支持按指定期间查看全部明细及完整筛选集的真实合计。默认只查已过账单据；草稿与取消单必须明确指定，不能混入有效业务合计。

## 第三轮已确认

- Q9：一个用户允许创建多枚令牌，以名称区分手机、电脑等用途，也允许多个客户端共用一枚。令牌由系统生成，后台点击查看／复制。
- Q10：采购／销售及往来明细未指定日期时默认本月，使用Asia/Shanghai并明确返回实际日期范围；可指定其他期间。当前库存与当前往来余额仍为当前状态，不套用日期默认值。
- Q11：采购／销售保留原始数量／金额、截至当前仍有效的退货及净数量／净额。例如9月售出10件、10月有效退回2件，之后查9月返回原始10、有效退货2、净8。不能解释为该期间收付款或退款现金流。
- Q12：往来明细可按期间查询全部单位或指定单位；对账单必须先确定准确的往来单位。双身份未指定方向时分别给客户／供应商结果，不自动抵扣。

## 第四轮已确认

- Q13：新令牌加密保存，保留认证摘要；沿用现有稳定配置，不增加独立密钥服务或启动步骤。数据库恢复时保留同批配置；更换所依赖密钥后，旧令牌认证继续可用，但查看需原配置或重置。
- Q14：用户明确要求开放实际成交价、参考价、联系方式、地址、开票资料、税号、银行账号和备注。按业务所属对象返回，不再沿用首版对此类字段的隐藏要求，仍继承绑定用户的业务权限。
- 新增信息区分当前档案与历史快照：参考价、往来开票／银行资料为当前档案值；已过账单据的商品及送货资料保持历史快照，不能相互替代。

## 已收敛的设计树

1. 凭证管理：管理员管理、多枚／共用、系统生成、查看复制、可选有效期、默认永久、延期、停用／启用、重置与旧摘要凭证兼容。
2. 客户端配置：原值token请求头与Bearer兼容，无需新增环境准备；冲突凭证及界面复制行为在规格中规定。
3. 查询：保留四工具，扩充采购／销售及往来明细／对账；按对象或日期查询，默认本月、已过账；金额／数量、退货净额、双方向和当前档案／历史快照沿用业务口径。
4. 业务字段：开放参考价、真实成交价、联系／开票／银行资料和备注；按工具所属业务对象组织返回。
5. 实施：架构决策见 [ADR-0017](adr/0017-recoverable-mcp-tokens-and-inherited-query-permissions.md)，接口、工具及工作包见 [实施规格](mcp-next-spec.md)。

## 核查依据

- 凭证原来已落库，但只存摘要，默认30天且CLI最多90天，无法还原原值。
- 项目没有通用敏感配置加解密模块；现有稳定密钥为 `jwt.secret`。备份说明已要求数据库与同批服务配置一起保存。新加解密需小型明确实现。
- 商品及往来Service已有本轮要求的当前档案字段。
- 采购／销售 `ItemPage` 已有全匹配集汇总与有效退货／净额；单据和行备注在 `Detail` 中，因此设置对应只读详情工具，不让客户端只能看到不含备注的跨单列表。
- 销售送货资料使用过账快照；银行账号来自当前往来档案，不是历史付款账户。往来摘要／资金备注／冲销原因来自账务记录的description。
- 对账单无分页、往来明细存在内存分页的现状须在实施时处理，不能把截取后的输出当作完整对账结果。
