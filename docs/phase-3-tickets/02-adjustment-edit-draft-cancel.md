# 02：库存调整草稿编辑、版本冲突与草稿取消

**GitHub issue:** [#9](https://github.com/EziosWJ/simple-inventory/issues/9) · `ready-for-agent`

## Parent

Phase 3 库存基础规格：https://github.com/EziosWJ/simple-inventory/issues/7

## What to build

经营者可修改已保存的调整草稿，或填写原因将不用的草稿取消；两人同时修改同一单据时明确提示版本冲突。本任务在既有草稿页面交付完整维护路径，编辑和草稿取消均不改变库存。

## Acceptance criteria

- [x] 草稿可编辑明细、原因和说明，沿用建档校验与唯一商品规则；单号、创建人、创建时间不能在编辑时覆盖。
- [x] 编辑携带用户核对的版本，保存成功后版本变化；旧版本覆盖被拒绝并提示刷新，失败保留用户输入，不能静默写入过期内容。
- [x] 状态与版本校验必须在写入时有效，避免事务外读取后覆盖他人修改；并发修改同版本最多一份成功，不能丢失更新。
- [x] 取消草稿前界面确认并必填原因；成功转为 CANCELLED，保存取消原因、实际操作人、时间，不产生库存余额或流水。
- [x] 已取消草稿可在状态筛选与详情中查看，不允许编辑、重新过账或删除；取消前编辑竞争不允许未确认的新内容被取消。
- [x] 重复取消请求不重复变更状态或产生业务效果；过期版本或不兼容状态提供明确错误，不依赖客户端按钮防重。
- [x] 设置只能编辑 DRAFT 的服务端状态边界；后续过账后继续复用该边界，不允许该编辑接口覆盖已过账内容。
- [x] 公开 HTTP 场景覆盖修改、旧版本冲突、并发保存、取消原因空白、重复取消、已取消不可编辑及审计失败回滚；UI 展示版本冲突和取消记录。
- [x] 本任务仅实现草稿取消，已过账取消和反向流水由后续任务交付，不伪造库存数据。
- [x] 沿用现有登录认证和已登录账号访问范围，记录实际操作人；真实菜单按现有角色菜单规则接入，不使用 mock 权限充当后端授权。
- [x] 业务修改和操作审计同事务，失败整体回滚；如新增 schema/seed，使用双库逻辑版本同步的 Goose 迁移，不改写旧版本。
- [x] 公开 HTTP 行为和真实数据库验证在 PostgreSQL/文件型 SQLite 上通过；新增 contract 确实被现有数据库门禁选中，跳过与未执行项如实报告。
- [x] API 源注解与 Swagger 重新生成，实际页面路径可演示；执行后端 tests+vet、前端 lint/build 及与改动对应的双库检查，报告结果。

## 实现与验收记录

2026-10-01：#9 已在当前工作区实现，尚未提交、推送或关闭 GitHub issue。

- 编辑使用 `PUT /api/v1/inventory/adjustments/:id`，提交 `{version, items}`；草稿取消使用 `POST /api/v1/inventory/adjustments/:id/cancel`，提交 `{version, reason}`。成功返回完整单据并递增版本；旧版本、终态及重复取消返回 409，不存在返回 404，非法输入返回 400。
- 版本与 DRAFT 状态在事务内条件写入时校验，明细替换或取消元数据与审计同事务提交。单号、创建人、创建时间保持不变；取消保留明细及实际操作人、UTC 时间和原因。
- 双库新 schema 10 保存取消记录，seed 保持 7，不改既有 schema 9。PostgreSQL/SQLite 的 schema 9→10→9→10 验证保留旧草稿及明细；隔离 SQLite 环境原 #8 草稿升级后也实际读取成功。
- `GOFLAGS=-v task db:check` 通过，后端 tests/vet 与双库全量集成没有跳过项。新增 `TestPostgresInventoryDraftMaintenanceContract`、`TestSQLiteInventoryDraftMaintenanceContract` 实际执行，覆盖并发编辑、编辑取消竞争、旧版本、空白原因、重复取消、终态边界、商品资料重新确认、不同登录操作人，以及编辑/取消审计失败整体回滚。
- `task frontend:lint frontend:build` 通过；构建保留 Browserslist 数据过期和主包超过 500 kB 的提示。
- 真实浏览器验收通过：保存编辑后数量与版本变化；编辑冲突保留输入并明确确认后重载；取消冲突保留原因且原单保持草稿；空原因禁用提交；成功取消展示记录且隐藏维护操作；旧单位保存被拒绝，用户重新选择确认新单位后保存成功。无浏览器运行错误。
- Swagger 从固定源注解使用 swag v1.8.12 重新生成。本任务对应检查均已执行；没有新增余额、流水或过账能力。
