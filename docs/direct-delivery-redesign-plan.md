# 直送单与销售采购来源需求讨论

状态：整体方案已由用户授权转为规格、发布任务并开始实现；规格为 GitHub #78。T01～T05 的实现已完成，统一验收记录见[进度文档](direct-delivery-redesign-progress.md)。代码提交仅保存在本地，GitHub 子任务保持打开。

## 已确认

- Q1：直送单以客户已经收货为确认依据。未交付时保存草稿；确认时同时生成并过账采购单、销售单，两边同事务生效，失败整笔回滚，重复操作不能重复生成。
- Q2：首版一张直送单对应一个供应商、一个客户，多供应商分别建直送单。
- Q3：普通销售的采购来源记录到采购明细及数量，一张销售可以关联多个采购单；暂不记录配件序列号。来源记录与原直送关联的业务约束分开设计。
- Q4：装电脑实际按配件报价并销售，沿用配件库存扣减。若经营者按整机商品经营，则沿用整机入库、整机销售流程。本次不引入组装单、自动配件转整机或新的整机库存逻辑。
- Q5：直送确认沿用采购增加、销售减少的成对库存流水，明确标记直送；两边同事务完成，库存余额净变化为零。
- Q6：普通销售采购来源为人工追溯记录，不占用采购明细数量，不限制跨销售累计来源数量；不能据此保证单件实物出处。
- Q7：来源选填，允许只记录部分销售数量；一条销售明细可关联多个相同商品的已过账采购明细，来源数量合计不能超过该销售明细数量，未记录部分明确展示。
- Q8（按后续澄清更新）：直送部分退货可以先取消原直送单及对应采购、销售，再根据实际情况独立新建直送单；原单和取消记录保留，新单与旧单没有联动重开关系。
- Q9：直接退给供应商时按保留商品及数量取消重开，全部退回时整单取消；退回店内且尚未退给供应商时，沿用销售退货流程，保留采购并增加店内库存。
- Q10（已被后续澄清替代）：不提供联动的“取消并重开”。整单取消原直送及其采购、销售是一项操作；之后独立新建直送是另一项操作，新建失败或未新建不影响原取消结果。不预填、不关联旧新单，不限制新单沿用原交易对象或日期。
- Q11：新直送单生成的采购、销售可查看、打印、追溯，不能各自独立修改或取消；更正统一由直送单入口办理。销售退回店内的入口可以从直送详情进入。
- Q12：普通销售过账后允许补填、修改采购来源，记录操作人、时间和修改前后内容；不改变已过账商品、数量、价格、库存和往来。
- Q13：取消重开保留原收付款，调整交易金额后按往来单位总余额形成欠款或待退款，实际退款另行登记；不将收付款重新分配到新单，客户与供应商方向各自结算。
- Q14（已被后续澄清替代）：独立新单按普通新建流程填写业务日期，不自动继承原日期。原单取消和新单过账分别使用实际生效时间并保留历史流水。
- Q15：直送支持销售侧附加服务，仅进入销售单，不进入采购单或库存。按后续澄清，新单独立填写价格和服务，不自动继承原内容或按退货比例调整。
- Q16：已有直送数据保留原规则并标记“旧版直送”；包含仅一侧已过账的旧单和已有草稿，不强制转换。新业务统一从独立直送单创建，普通销售原直送选择器改为采购来源功能，旧草稿仍有完成原关联流程的入口。
- Q17：客户先退回店内、经营者后续再退给供应商时，从直送详情办理对应采购退货，沿用现有规则，只扣库存并减少供应商应付，不再取消重开。
- Q18/Q24：有生效退货时沿用现有约束，禁止整单取消并显示阻止操作的退货单；实际退货继续原流程，退货录错时先按原规则取消退货，再取消直送，不自动取消关联退货。
- Q19：采购来源不按采购与销售业务日期先后硬性限制；来源采购业务日期晚于销售时提示核对，用户明确确认后允许关联。
- Q20：已关联采购取消或退货后保留来源，展示当前状态及退货情况；取消提示核对，不自动删除或修改销售，人工更正保留历史。
- Q21/Q22：原先提出的联动重开修改范围、纯服务自动转换未获确认且被用户简化原则取代；独立新单按正常录单规则填写，剩余服务需要记录时独立录普通销售，不增加转换逻辑。
- Q23/Q25：复用生成销售单的送货单打印，支持金额显隐，客户打印件不展示采购价格及供应商结算信息，不新增直送打印模板。

## 最新简化原则

取消与之后的新建独立，互不影响。不引入联动重开、更正链、继承日期价格、交易对象限制或保留服务的自动转换；经营者按实际情况另行填写直送或普通销售，沿用各自录单规则。对于已有退货等情况复用现有规则，有生效退货时禁止整单取消。

## 最终方案摘要

### 独立直送单

- 新业务使用独立入口，每单一个供应商、一个客户，实物明细共用商品与数量，分别填写采购价、销售价，可附加仅销售侧的服务。
- 保存草稿不生效；客户收货后确认，在同一事务中生成并过账采购、销售，库存和往来流水、状态、审计一起提交。失败全部回滚，重复请求不重复记账。
- 实物保留成对采购增加、销售减少的库存流水，标记直送，整笔确认后的库存净变化为零；应收、应付分别记录，客户方向与供应商方向不自动抵扣。
- 两张生成单据可查看、打印、追溯，不能各自独立修改或取消，整笔取消从直送入口办理，在同一事务中冲销对应采购和销售并保留原流水、历史记录及实际收付款。
- 直接退给供应商时可取消整个原直送，再按实际情况独立新建；取消与新建没有联动事务、自动继承或旧新单更正关系。
- 退回店内先走销售退货，随后退供应商再走采购退货；存在生效退货时禁止整单取消，沿用原退货处理规则。
- 新单自行填写业务日期；库存、往来按实际生效时间记录，不倒签历史流水。款项仍按往来单位总余额结算，实际退款另行登记。
- 客户签收复用生成销售单的送货单，沿用送货资料快照和金额显隐，不展示采购价格。

### 普通销售采购来源

- 原直送选择器改为可选的采购来源记录，按销售明细关联多个相同商品的已过账采购明细，记录各来源数量；采购明细可被多张销售引用。
- 单条销售明细来源数量合计不超过原销售数量，允许部分记录，未记录部分明确展示；不占用采购数量、不限制跨销售累计来源数量、不改变库存或往来。
- 来源为人工追溯参考，不自动分配库存批次、推断单件身份或计算成本毛利；普通退货不因来源关联自动处理采购退货。
- 销售过账后允许补填、更正来源并记录修改前后内容及操作人、时间。销售业务内容继续遵守原过账锁定规则。
- 采购日期晚于销售日期时提示并要求明确确认；关联采购后续取消、退货不删除来源，显示当前状态并提示核对。

### 原有流程与兼容

- 配件报价、配件销售和配件库存扣减保持原业务规则；按整机商品经营时沿用整机入库、整机销售，不新增组装转换。
- 旧版直送保留原单、原关联、状态及操作规则，包括只过账一边和已有草稿；新旧入口明确区分，不强制把旧数据转换为新直送单。
- 不引入序列号、严格采购数量分配、逐单收付款核销或新打印模板。

## 原规格差异

现有 Phase 4 规格规定直送采购与销售分别过账、按实物商品汇总数量一致，允许两次过账之间库存暂增。新方案将直送录单和确认集中到独立直送单；普通销售采购来源不沿用直送的一对一关联与整单数量一致限制。
