# MCP 凭证支持后台恢复查看，查询权限动态继承系统用户

2026-10-15，用户实测首版MCP可用后，确认在后台统一管理凭证，默认永久、可选期限及延期，并要求随时查看和复制。新凭证保留认证摘要，同时加密保存可恢复原值；管理员查看时解密，列表默认遮罩。这样满足多客户端日常配置，不再只能在签发时抄录一次；代价是备份恢复必须保留同批服务配置。旧摘要凭证保持可用，重置后才获得恢复查看能力。

为避免额外部署步骤，以现有 `jwt.secret` 经独立用途派生得到显示加密密钥，采用带认证的版本化密文和随机nonce，不新增密钥托管服务。摘要认证不依赖这把密钥；密钥变更会影响旧凭证显示，管理员可以恢复原配置或重置。此处是为保持现有部署流程作出的取舍，不建设通用密钥轮换系统。

用户还确认不再逐令牌选择工具。所有有效凭证统一继承绑定用户当前拥有的MCP只读查询权限，新增查询随已有业务授权自动开放；旧scope快照不再限制工具集。保留系统用户绑定、即时撤权、停用和重置，不建设另一套业务角色体系。

系统由用户本人使用，本轮明确开放参考价、联系方式、开票资料、税号、银行账号和备注；通过显式业务DTO区分当前档案与历史快照，不延续首版对此类业务字段的隐藏。上述决定更新 [ADR-0016](0016-private-mcp-service-and-user-bound-tokens.md) 中“仅存摘要”和“逐凭证scope交集”两项，进程内复用业务Service与用户绑定原则保持。产品决定已确认，代码实施以[后续规格](../mcp-next-spec.md)为准。
