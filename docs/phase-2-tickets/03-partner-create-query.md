# 03：往来单位建档、双重身份和分页查询

**GitHub issue:** [#4](https://github.com/EziosWJ/simple-inventory/issues/4) · `ready-for-agent`

## Parent

- Phase 2 基础资料规格：https://github.com/EziosWJ/simple-inventory/issues/1

## What to build

经营者可以为单位或个人建立统一往来单位档案，同一档案可同时是客户和供应商；可以维护主要联络与选填开票资料，分页筛选并查看详情。个人客户只输入名称即可建档。本任务交付完整建档查询路径，包括双库、API、菜单、UI、审计与验证，可独立演示。

## Acceptance criteria

- [ ] 提供真实往来单位菜单并授权 ADMIN，沿用既有登录认证与本轮确认的 API 访问范围，不依赖商品模块。
- [ ] 名称、单位/个人分类必填，客户/供应商至少一种身份；双重身份只保存一份档案，无身份提交被拒绝。
- [ ] 个人客户表单默认个人分类和客户身份，只输入名称即可提交；其他资料均允许为空，编码空值自动生成。
- [ ] 支持一个主要联系人、电话、地址、备注及可选开票名称、税号、注册地址与电话、开户行、账号，开票资料不成为个人客户建档前提。
- [ ] 手工编码去除首尾空白并统一大写，往来单位范围内唯一；名称可重复，编码并发冲突不能覆盖或合并已有档案。
- [ ] 可按编码、名称、联系人、电话关键词查询，并按单位/个人分类、客户或供应商身份、启用状态筛选；双重身份档案在两种身份筛选中均可查询到。
- [ ] 分页总数、稳定排序与现有契约一致，可以查看所有已保存资料的详情，表单错误明确显示并保留输入。
- [ ] PostgreSQL/SQLite schema 与菜单 seed 迁移逻辑版本同步，空库、升级与编码约束验证通过；沿用统一往来单位 ADR。
- [ ] 新增档案与审计同事务提交，双库验证审计失败时不留下档案。
- [ ] 公开 HTTP 测试覆盖单位/个人、双重身份、个人最小输入、可选开票资料、无身份拒绝、编码冲突、详情、筛选分页和未登录拒绝；被数据库检查入口实际执行。
- [ ] 完成页面建档查询演示、相关后端、前端及双库检查，Swagger 由源注解生成，报告未执行项。
- [ ] 本任务不提供编辑、启停、删除、应收应付、开票流程或导入导出；后续维护使用同一份档案。
