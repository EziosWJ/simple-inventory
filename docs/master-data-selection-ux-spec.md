# 商品与往来单位：直接搜索、快速选择与完整选择面板

## Problem Statement

经营者在筛选单据、查往来和录入采购／销售时，需要频繁查找商品、客户和供应商。现有选择器虽然可以搜索和分页，但先展开才能输入，把编码、名称、型号、联系人和电话拼成一段长文字，候选频繁换行；结果滚动、分页和关闭操作集中在窄浮层中。经营者需要反复展开、辨认和翻页，选中后的长摘要也占据表单空间。

现有列表主要通过对象 ID 筛选。只记得商品类别、型号片段或单位部分名称时，经营者仍需先选定一条档案，难以直接查出全部相关业务。当前资料更名后，只存在于已保存快照中的旧描述，也不能通过档案搜索找回。

录单换选还可能破坏人工输入：重复选中同一商品会重新带入参考价，换客户会覆盖送货资料。界面缺少完整候选键盘导航，选中商品后也没有顺畅进入数量填写。

## Solution

提供统一的「直接搜索 → 快速选择 → 完整选择面板」体验。经营者直接在字段输入关键词，附近展示最多六条有清楚信息层级的候选；没有输入时优先显示个人最近使用。点击候选完成选择，需要比较更多资料时，通过始终可见的「浏览选择」或「查看全部结果」打开约 800px 宽的居中 modal，沿用关键词，以表格比较和分页。

列表明确区分「关键词查询」和「指定对象」：输入“硒鼓”可以查全部匹配商品的相关业务，选中某条商品则只查该商品。录单必须选中真实档案。多个关键词可以跨字段匹配同一对象，历史查询同时使用当前档案和该记录已有的历史快照。

以名称、型号／规格和联系方式帮助辨认，弱化编码，避免重复资料；支持鼠标、键盘和中文输入法。换选时保护手工成交价、数量、备注与送货资料，取消换选保留原内容。首批覆盖采购／销售列表与录单、往来余额／明细，公共能力随后供库存和收付款等场景复用。

1. As a 店铺经营者, I want 直接在商品或往来单位字段输入, so that 省去展开后寻找另一个搜索框的动作。
2. As a 店铺经营者, I want 输入后在字段附近看到少量候选, so that 可以快速完成常见选择。
3. As a 店铺经营者, I want 快速候选最多展示六条且不带分页按钮, so that 不必在狭窄浮层中滚动后再翻页。
4. As a 店铺经营者, I want 字段旁始终有浏览选择入口, so that 不记得关键词时仍能查找资料。
5. As a 店铺经营者, I want 从快速结果进入完整选择面板, so that 能查看当前关键词的全部候选。
6. As a 店铺经营者, I want 完整选择面板沿用已输入关键词, so that 不必重复输入。
7. As a 店铺经营者, I want 在宽敞的居中 modal 中按列比较资料, so that 容易区分相近型号和同名单位。
8. As a 店铺经营者, I want 完整面板显示真实总数和分页, so that 能浏览超过第一页的档案。
9. As a 店铺经营者, I want 点击面板中的一条记录就完成选择, so that 减少额外确认动作。

## Implementation Decisions

- **首批范围**：采购与销售列表的商品／往来单位筛选、采购与销售完整录单中的对象选择、往来余额和往来明细的单位筛选。库存调整、库存流水、收付款、退款及往来记录等其他入口留待随后接入；本规格不以全部入口迁移作为交付条件。
- **共同能力与业务边界**：优先演进已有分页档案选择能力，统一直接输入、快速候选、结构化展示、最近使用、modal、分页及键盘交互。商品／往来业务包装提供检索字段和资料展示；页面负责历史或录单可选范围、选择结果的接纳、数据带入、覆盖确认及业务校验。共用组件不承担采购／销售的金额、送货或过账规则，不建立配置驱动的通用业务平台。
- **三层交互**：字段可直接输入，快速结果最多六条，不放分页控件；始终提供浏览选择，另从快速结果进入查看全部。完整面板为约 800px 宽的居中 modal，沿用关键词，提供表格、真实总数及稳定分页。面板宽高受可用视口约束，表格不能撑破页面；精确字号、列宽和页容量由实施者按现有设计系统决定。
- **选择与取消**：完整面板单条记录点击后完成选择并关闭；若业务换选需要保护确认，所有新值在确认接纳后一起生效。关闭、Esc、外部取消或取消覆盖确认不改变原对象和人工输入。快速浮层、完整面板和覆盖确认的焦点及关闭顺序独立可预测；只关闭当前活动层，不误关父表单。
- **展示层级**：往来单位名称优先，联系人／电话、客户／供应商身份辅助辨认；商品名称、型号／规格优先，品牌、类型与单位辅助辨认；编码降低视觉权重。重复名称／联系人和空字段自然省略，匹配文字突出。完整面板按列比较且支持查看长文本全文，选中后保留简洁摘要与详情查看方式。历史停用明确标示，当前资料与历史快照不可相互覆盖。
- **最近使用**：按真实登录账号、当前浏览器和业务场景保存最近接纳的选择，至少区分客户、供应商、采购商品与销售商品，按最近选择顺序去重。仅浏览、输入或取消换选不记入最近使用。空关键词优先显示适用最近对象；没有记录时说明暂无最近使用并提供普通候选。已有输入关键词时按检索结果展示，最近顺序不压过搜索相关性。
- **最近资料有效性**：记录内部 ID，在显示和选择时读取最新资料并核对当前场景；录单中排除停用、身份不符或类型不符的对象。历史场景保留可追溯对象。账号尚未加载时不使用共享账号缓存，切换账号同步切换记录；本地存储不可用或内容损坏时降级到正常搜索。存储键、保留容量与读取组织由实施者决定，不能混用草稿保存／过账恢复标识。
- **查询模式**：同一商品或往来单位筛选字段只处于空条件、关键词或精确对象之一。输入文字后明确执行查询，显示「商品关键词：…」「往来单位关键词：…」；点选候选后绑定 ID 并显示指定对象摘要。完全同名也不得自动指定档案。录单只接纳具体档案，未选中的查询文字不能保存为对象。
- **已提交条件与查找草稿**：重新查找和编辑输入不立即丢弃原精确选择；新关键词明确应用或新对象被接纳后再替换。取消查找保留原条件，显式清除才移除该字段条件。组合查询、重置和条件切换重置业务结果页码，翻页不丢已选 ID。通过既有路由查询及返回机制保留已应用模式、关键词／ID、日期、状态、方向、分类与页码，兼容旧 ID 链接。
- **分页来源**：候选和业务记录都使用服务端完整查询及既有分页信封，不加载固定首批 500 条进行客户端全量筛选；不得把档案搜索第一页的 ID 当作全部匹配对象。关键词业务结果中的单据总数、行数和分页基于完整记录计算，同一单据多个匹配明细不重复计数。
- **多关键词语义**：首尾去空白，按空白拆分多个非空字面词；每个词在同一对象的适用字段中 OR 匹配，词之间 AND 匹配。商品字段为编码、名称、品牌、型号、规格；往来字段为编码、名称、联系人、电话。允许跨字段，但商品条件必须由同一商品／同一条明细对应的资料满足，不将不同商品行各命中一个词拼成单据命中。商品条件、往来条件与日期／状态等业务条件组合时各自成立。
- **字面与排序**：中文按字面片段匹配，ASCII 字母大小写及百分号、下划线、反斜杠的处理在 PostgreSQL／SQLite 一致，输入文字不作为数据库通配符扩展结果。档案检索中编码或名称完全匹配优先，其余采用稳定次序，快速结果与 modal 使用同一检索口径。具体并列次序由实施者确定。候选相关性排序不改变业务列表已有单据排序、往来金额排序或流水生效时间排序。
- **公开接口扩展**：扩展商品、往来档案搜索，并为首批采购／销售、往来余额／明细公开查询增加对象文字筛选能力，保留原有 ID、分页、日期、状态、方向和分类语义。精确 ID 与同字段关键词互斥，冲突参数明确校验并报错；商品字段与往来字段可分别使用不同模式。新查询字段和返回的必要历史命中说明采用兼容扩展，具体命名与响应组织由实施者确定，不增加测试专用接口。
- **历史匹配**：历史业务文字筛选同时使用当前档案和该业务记录实际已保存的描述。每个词必须匹配同一对象的当前字段或该条记录的快照字段，不能跨不同业务对象拼接。历史快照参与命中的结果明确标注「匹配历史资料」，必要时展示已有快照片段帮助核对；查询提示说明实际覆盖范围。候选档案查找仍展示当前档案，因此候选无匹配不代表历史业务无匹配，历史列表仍允许提交文字查询。
- **历史字段边界**：采购／销售商品明细可使用已保存的编码、名称、型号和规格；已过账销售可使用冻结的客户名称。商品品牌、采购供应商名称／联系方式、往来余额及明细的单位描述均没有对应历史快照，只按当前档案匹配。销售送货联系人、电话和地址属于该次送货资料，不并入通用客户档案关键词搜索。不回填或伪造缺失快照，不因搜索覆盖当前档案而改变旧记录的显示和打印。
- **历史状态兼容**：历史查询不因对象停用或移除当前客户／供应商身份而丢失已有业务；选项与记录以内部 ID 关联。旧草稿独立按 ID 读取原选择并显示状态问题，不因当前候选页缺少该 ID 而清空。新采购只选启用供应商和启用实物商品，新销售只选启用客户及启用实物／服务，保存与过账仍按现有服务端规则复核。
- **往来余额范围**：单位关键词／ID 只筛选下方列表，保留余额分类和方向规则；全店概览、单位数量及前十名排名继续覆盖全店。与既有全店概览和款项办理体验规格衔接，不把筛选结果重新解释为全店金额。
- **往来明细口径**：关键词模式可以列出多个匹配单位的记录，逐条明确所属单位及客户／供应商方向，原前后余额仍属于该单位该方向，不合并为跨单位滚动余额。指定一个单位、一个方向及期间后，沿用期间余额和对账打印；关键词尚未收敛为精确单位时，不生成合并期间余额或跨单位对账单，并提示先指定单位。来源返回保留原文字或精确查询上下文。
- **键盘与可访问性**：所有操作可用鼠标完成，同时支持上下方向键移动可见候选高亮，Enter 选择明确高亮的可选对象，Esc 关闭当前选择层并恢复焦点。没有明确候选高亮时，列表筛选 Enter 执行关键词查询；录单 Enter 不提交父表单，不保存或过账。输入法 composition 期间确认中文不触发选择、查询或提交。提供正确的 combobox／listbox／option 或等价语义、可见焦点和加载状态反馈；选中商品并被业务接纳后焦点进入该行数量框。
- **异步反馈**：保留防抖、请求结果所有权和独立读取已选 ID 的能力。关键词、页码或场景变化时旧响应不得覆盖当前结果；加载、无结果、失败、重试、已选资料读取失败明确区分。读取失败保留原 ID 和已有输入，不把未知资料当作空选择。关闭后的迟到请求不得重新打开面板或改写表单。
- **重复选择与初选**：重复接纳相同 ID 是内容无变化的操作，不重新写入人工单价或送货资料。首次选择商品继续带入当前业务适用参考价、类型与单位，参考价为空沿用既有可录入行为。重复选择不绕过服务端对停用或档案变化的复核。
- **换商品保护**：保留行数量与备注。没有手工改价时沿用新商品适用参考价；已手工改价时提供保留成交价或采用新参考价的明确选择。单位变化时要求核对原数量在新单位下的含义，不自动换算。取消保护确认时原商品、类型、单位、单价、数量与备注整体保持。继续支持同商品分行和不同成交价，不自动合并明细。
- **换客户与清除保护**：首次选择客户沿用既有送货资料带入；换客户涉及覆盖手工修改的联系人、电话或地址时，明确选择保留送货资料或采用新客户资料。人工清空是有效输入，不能当成尚未填写。清除是显式操作，不能借清除再选择绕过人工输入保护；取消时原客户和全部送货字段保留。普通无覆盖选择直接完成，保护确认只用于实际人工内容覆盖及商品单位变化。
- **架构与数据**：保持模块化单体、Handler → Service → Repository 及显式组装，Service 不依赖 Gin、GORM 或具体数据库。数据库差异局部化，保持 PostgreSQL／SQLite 一致；最近使用保存在浏览器，无新增业务表需求。如实施确需索引或其他 Schema 变更，必须使用双库同步 Goose migration，验证空库和旧数据升级，不使用 AutoMigrate。
- **业务一致性与文档**：保留统一往来单位、商品类型／基本单位历史锁定、客户与供应商余额分开、总余额收付款、幂等、并发版本、审计及事务规则。修改 REST API 时同步源注解，运行项目固定的文档生成任务并审查生成差异；生成文件须由源定义重新生成。

## Testing Decisions

- **用户已确认的测试边界**：以真实浏览器操作既有公开 API 的完整链路作为交互主验收入口；用既有 PostgreSQL／SQLite 公开 HTTP 集成契约补充检索、分页、历史匹配和业务保存结果。不增加测试专用业务接口，不以组件内部函数或 Repository 调用替代用户行为验收。
- 好的测试验证可观察结果：用户能否找到正确对象、当前查询模式、候选辨认信息、焦点位置、提交是否发生、保存后的实际对象／数量／成交价／送货资料、业务结果总数及历史命中说明。避免绑定组件树、CSS 类名、状态变量、缓存 JSON 格式或 SQL 写法。
- 复用已有 Phase 5 采购搜索、销售草稿、单据查询及往来查询的真实浏览器验收方式，在隔离 API 和数据库中通过公开业务接口造数，再由页面完成查找、换选、保存、返回和刷新。候选布局专项验收及已有菜单搜索的键盘／输入法经验可作补充，不替代真实链路。
- 复用既有档案搜索、采购／销售单据查询、往来余额／明细的双库公开 HTTP contract。公开接口用于验收真实业务输入与输出，已选 ID、历史快照和持久字段由公开读取核对，不创建测试专用端点。
- 建立超过 500 条商品和往来档案、超过一页的业务记录，包含同名对象、相近型号、无可选对象和长名称；验证快速结果上限、完整 modal 全量分页、精确排序优先级、稳定翻页、按 ID 保留选择与没有固定首批上限。
- 验证多个词跨不同字段命中同一对象、重复／连续空白、中文、ASCII 大小写、字面百分号／下划线／反斜杠；设置不同商品行分别命中不同词的反例，确认不能拼成一次匹配。确认多个匹配明细不重复计算单据总数，并覆盖日期、状态、方向及分类组合。
- 验证首批业务的文字和 ID 模式互斥、冲突参数、空条件、模式切换、查询页码重置、旧 ID 链接和已应用条件的刷新／详情／来源返回。浏览器的搜索草稿与已应用条件分别验证，取消重新查找不能改变原条件。
- 先保存及过账业务，再更名、修改型号或移除身份／停用相关档案；验证旧商品快照与销售客户名称仍可命中，并显示历史匹配说明。验证缺失快照字段不被伪造、候选无当前档案匹配仍可查询历史业务、历史空快照不被新档案值写回。
- 浏览器覆盖结构化候选、名称／联系人去重、身份／类型／单位、匹配文字、长文本全文、简洁已选摘要、停用标识、加载／空／错误／重试、迟到响应与已选资料读取失败。
- 验证最近使用的实际选择顺序、去重、没有记录的候选、账号与浏览器隔离、业务场景适用范围、取消换选不计入、停用／身份变化后重新核对和本地存储不可用时的搜索降级。使用行为验证，不锁定内部存储格式。
- 浏览器覆盖全鼠标流程、上下方向键、高亮后 Enter、无高亮时的列表关键词查询、录单 Enter 不保存或过账、中文输入法确认、Esc／Tab／焦点恢复、选择商品后数量焦点，以及 modal 只关闭当前活动层。检查桌面常用尺寸和缩放下不溢出、分页可达、父页面布局稳定。
- 通过真实表单与公开保存读取验证初选参考价、重复选同 ID 不覆盖、换商品保留数量／备注、人工价保留或采用新参考价、单位变化核对、换客户保留或采用送货资料、明确空值和取消换选整体保留。回归同商品不同价分行及服务销售，确认不自动合并。
- 验证往来余额搜索仅改变列表且全店概览／排名不变；往来明细宽泛查询逐条明确单位和方向，前后余额不跨单位累计；指定单位和期间后仍能查询期间余额、打开来源并打印既有对账单。
- 回归首批采购／销售保存、编辑、过账及既有并发／审计边界，确认选择改造不改变库存和往来生效规则；完整回跑数量按风险及实际修改范围确定，不为静态展示变化新增镜像实现的测试。
- 调试先执行最小相关检查；数据库相关先定向 SQLite，再定向 PostgreSQL。新增双库 contract 使用 TestSQLite、TestPostgres 前缀并核对任务与 CI 各选中一次；如涉及 Schema，补双库空库与旧数据升级。定型后运行数据库兼容门禁（已包含后端检查）、前端 lint／build，API 变更运行固定文档生成任务；报告所有未执行项及人工试用状态。

## Out of Scope

- 一次迁移全部业务页面的选择器；库存、库存调整、库存流水、收付款／退款和往来记录等其他入口的实际接入留待后续工作。
- 商品批量勾选添加、批量修改价格、自动合并明细或重做采购／销售录单页面整体结构。
- 手动收藏、全店共享使用排名、最近使用跨设备同步、账号偏好服务和新的业务存储表。
- 全局搜索引擎、拼音索引、模糊纠错、全文检索服务或商品别名体系。
- 在候选中新增价格、库存、历史成交价或毛利等业务辅助信息；已有参考价带入继续保留。
- 在选择面板中新增嵌套建档、资料维护或新建后自动回填流程。
- 补造不存在的历史名称、品牌或联系方式；将单次销售送货资料当成通用客户档案历史；改写已过账快照。
- 跨单位合并往来余额或期间对账、客户／供应商自动抵扣、逐单核销、按总余额推断具体单据结清。
- 库存成本、报表、业务单据生命周期、权限系统或部署架构的改造；手机优先适配另行讨论，首批维持电脑浏览器使用范围。
- 重新实施全店往来概览／排名或款项办理流程；本规格仅与其查询范围和导航规则协调。
