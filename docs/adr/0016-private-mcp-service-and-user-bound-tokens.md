# MCP 进程内复用业务服务，使用绑定系统用户的独立凭证

店铺需要从 Cherry Studio 查询商品、库存和往来余额。2026-10-15 需求访谈确认：MCP 在现有 Go API 进程中直接调用业务 Service，保留原业务规则及模块边界；不额外部署业务代理或允许 Agent 直接查询数据库。该选择减少首批部署和规则重复的成本，代价是 MCP 接入随 API 一同发布，需要验证既有业务入口兼容。

MCP 凭证与网页登录会话分开，绑定实际系统用户，工具权限取凭证 scope 与该用户当前有效业务权限的交集。这样可以单独撤销某个客户端访问，同时立即继承账号停用和业务撤权；代价是新增凭证持久化、生命周期管理及双库迁移，不直接复用已有 Web JWT。首批仅开放只读工具，身份绑定父亲账号，在同机隔离环境验证后再安排真实业务接入。

这不改变现有 REST 的授权行为，也不代表原 REST 已具备全面细粒度鉴权；MCP 独立执行服务端授权。业务写入与审计继续遵循 [ADR-0006](0006-atomic-operation-audit.md)。实现范围及验收以 [MCP V1 规格](../mcp-server-v1-design.md) 为准。
