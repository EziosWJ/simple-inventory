# 02：采购完整录单页与可靠草稿保存

**GitHub issue:** [#41](https://github.com/EziosWJ/simple-inventory/issues/41) · `ready-for-agent`

## Parent

[Phase 5 规格 #39](https://github.com/EziosWJ/simple-inventory/issues/39)

## What to build

经营者在独立采购录单页新建或编辑草稿，清晰核对商品和合计；网络中断后能确认原保存结果，重试不重复建单，双人编辑不会相互覆盖。

## Acceptance criteria

- [ ] 新建/编辑为可直接访问和刷新的完整页面，交易对象、业务日期、明细、合计、状态和保存草稿分区清楚，复用现有表单模式。
- [ ] 接入已交付搜索，保留日期、数量、参考价、同商品分行、单位/类型确认、准确金额及现有供应商/实物规则。
- [ ] 新页面创建和编辑携带稳定 requestKey；同操作人同操作同内容的并发或重试返回同一结果，同键不同内容冲突；旧客户端不传键保持兼容。
- [ ] 草稿、明细、成功请求结果和操作审计同事务持久化，失败回滚；重启后可查询原保存结果，不增加库存或应付。
- [ ] 响应丢失后核实原操作而非再次新建；原编辑之后又被他人修改/过账时，能区分原操作成功与单据当前版本/状态。
- [ ] 两会话同版本编辑时拒绝旧版本，保留输入并提供重新加载；丢弃未保存内容前确认，终态不作为可编辑草稿。
- [ ] 未保存返回、内部跳转、关闭/刷新有相应提醒；保存失败保留输入，不新增整张表单自动暂存。
- [ ] 原列表/详情/编辑链接迁至正确页面并保持现有取消及来源入口；最小恢复标识按账号隔离，不存完整未提交表单。
- [ ] 双库空库及旧数据增量迁移保持单据/明细 ID、版本、流水、快照和审计；契约覆盖重复、并发、不同内容、失败及响应丢失。
- [ ] 真实 UI 和相关门禁通过；新增契约 TestSQLite…/TestPostgres… 各只进一个数据库门禁，REST 注解及生成文档同步。
