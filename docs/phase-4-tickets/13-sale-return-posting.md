# 13：销售退货入库、应收抵减与逆序取消

**GitHub issue:** [#27](https://github.com/EziosWJ/simple-inventory/issues/27) · `ready-for-agent`

## Parent

Phase 4 规格：https://github.com/EziosWJ/simple-inventory/issues/14

## What to build

经营者确认销售退货，整单实物入库，先减客户总欠款再形成待退款；分次退货不超量、不产生金额尾差，取消保留实际退款并提示重新产生的欠款。

## Acceptance criteria

- [ ] 过账核对最新版本与原 POSTED 单，事务内按原明细累计额度校验，重复/并发不超退，服务退费明确拒绝。
- [ ] 按商品合计增加共享库存，原快照/单位/明细价格保持；同商品不同价及赠品行分别控制额度，整数加法溢出整单拒绝。
- [ ] 累计取整差额计算本次金额，全部退完累计等于原行额，小数量零金额仍有实物流水。
- [ ] 减少客户总余额而非原销售单未结额，先减欠款、超出部分待退款；例如欠400退500→待退100，供应商方向不变。
- [ ] 库存、往来、退货额度、状态和审计同事务；失败回滚，当前库存/流水识别销售退货并可打开来源详情。
- [ ] 原销售有生效退货时拒绝取消，事务内与原单取消竞争一致；退货取消后按仍生效记录恢复额度。
- [ ] 只能整单逆序取消每个原明细最新退货，任何一项不满足或反向扣库存不足整单拒绝；反向原金额、原数量、不重算其他记录。
- [ ] 取消不级联删改既有资金记录；本任务不提供实际退款，已退款取消退货形成新欠款及退款另行冲销的公开场景由后续退款任务贯通。
- [ ] 双库覆盖并发超退/重复、原单取消竞争、金额尾差、零额、停用历史、取消负库存、原资金保留及审计回滚；数量与金额分别对账。
- [ ] 沿用 JWT 和已登录账号业务范围，实际菜单按角色接入并授予 ADMIN，拒绝未登录请求；不以 mock 权限替代后端认证。
- [ ] 所需 schema/seed 使用 PostgreSQL/SQLite 逻辑版本同步的增量 Goose 迁移，不改旧版本、不用 AutoMigrate；保持现有业务数据与 API 兼容。
- [ ] 本任务业务维护与操作审计同事务，错误明确且保留表单输入；新增/修改 REST API 源注解与 Swagger 重新生成同步。
- [ ] 以公开 HTTP 和真实双库验证本任务行为，新增 contract 名含 Postgres/SQLite 并确实被门禁执行；相关后端 tests/vet、前端 lint/build 和数据库检查完成，报告失败、跳过和未执行项。
